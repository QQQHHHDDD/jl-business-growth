## 2. UAT3-FIX-01：首次进入页面闪动

### 根因

全局排查确认，认证或页面查询处于 pending 时，部分页面原先用通用全页 loading 块替换内容，使 App Shell、PageHeader 和页面主体先卸载再挂载；部分页面还把 `data === undefined` 与真实空数组混用，造成 Loading → 空状态 → 数据的视觉跳变。问题不是固定延时不足，也不是单一业务页面的接口错误。

### 修复

- 增加稳定的应用启动壳加载态，认证 pending 时保留侧边栏、顶部栏和内容容器。
- 增加带 PageHeader 的页面级 loading 骨架，保持标题、说明和主体尺寸。
- 明确区分 `isPending`、错误态和真实空数据；不在请求未完成时渲染 EmptyState。
- 对首页内部滚动区和目标页面容器保持既有尺寸契约。

### 验证

前端回归覆盖认证 pending、业务请求 pending、多个高频页面和 390px 移动端。E2E 在桌面和移动浏览器均通过；未使用 `setTimeout` 或隐藏页面掩盖问题。

## 3. UAT3-FIX-02：团队关系图 Handle 与成员节点颜色

### 根因

React Flow 的 Handle 必须继续存在以维持拓扑、自动布局和连线，但默认样式显示为明显黑色圆点；团队成员数据模型没有成员级颜色字段。

### 修复与数据模型

- 新增 Goose migration `00010_team_member_node_color.sql`，只向 `team_members` 增加 `node_color TEXT NOT NULL DEFAULT '#0f766e'`，并加入 `^#[0-9A-Fa-f]{6}$` 检查约束。
- 更新 sqlc、OpenAPI、生成代码、后端创建/更新/读取、导入导出和前端成员表单/详情/关系图。
- 颜色归属于当前账号拥有的成员记录；缺省值统一为 `#0f766e`。
- 编辑 Dialog 提供预设色板、自定义颜色、实时预览和恢复默认；前景文字按背景明暗选择以保持可读性。
- Handle 保留在 DOM 和 React Flow 拓扑中，但普通查看状态视觉透明，不改变父子关系、fit view、pan/zoom 或节点点击。
- 既有 `member_code`、父子关系和 ownership 规则未改变。

### 测试

## 5. UAT3-FIX-04：日历常用联系人加载

### 排查证据与根因

本轮对 `GET /api/calendar/contacts`、生成 client 路径、路由注册、SQL、权限中间件和数据库结构逐项核对：

- `calendar_contacts` 表来自 migration 9，当前开发库和测试库均已应用 migration 9 及 migration 10。
- 路由、OpenAPI 路径、前端 client 路径均为 `/api/calendar/contacts`，响应结构一致，没有发现字段或 NULL 扫描错误。
- 旧 UAT 发生时本机 8080 没有正在运行的后端进程，因此无法将错误归因于当前源代码的 HTTP 处理；这与“后端未重启/未使用最新迁移”的运行版本不一致最吻合。
- 使用当前代码启动隔离实例后，E2E 实际观测 `GET /api/calendar/contacts` 返回 200；创建联系人后刷新仍能读取。
- Phase 3 集成测试验证空列表、创建、重复邮箱冲突、更新、删除、跨用户隔离，以及管理员不能越权读取普通用户联系人。

因此，本轮没有用自动重试掩盖异常，也没有修改权限边界；修复重点是确保当前代码链路有真实回归覆盖，并保留“加载失败 + 重试”作为真实异常处理。当前版本空联系人显示正常空状态，有数据显示列表，异常显示错误态。
