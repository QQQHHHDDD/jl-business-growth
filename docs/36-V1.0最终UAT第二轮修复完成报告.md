## 5. 日期字段全局审计

### A 类：创建业务事实，默认账号时区的今天

- 今日工作：`work_date`。
- 营业额：`turnover_date`。
- 财务流水：`occurred_on`。
- 资金快照：`snapshot_date`。
- 团队成员：`joined_on`，仅打开新建表单时赋今天。
- 目标：`start_date`、`due_date`，仅新建时赋今天。
- 日历：新建默认今天 09:00～10:00；从日历日期/时段创建时以用户所选日期和时间为准。
- 学习快捷记录：`activity_date` 使用账号业务日期。

### B 类：筛选或统计，保留业务范围

- 数据统计：默认本周，可切换本月、自然年、财年、自定义；未改成单日。
- 复盘：按日/周/月类型保留对应周期语义。
- 工作量、营业额、财务和历史列表查询继续使用各自既有区间，不强制今天到今天。
- 邀请码过期时间属于管理限制，不是“今天发生的业务事实”，继续允许为空或由管理员选择。

### C 类：编辑历史记录，保留原值

- 目标、团队成员、日历日程、历史工作量和营业额编辑均从原记录初始化日期/时间。
- 切换到编辑态不会用今天覆盖已有值。

## 6. PV 舍入最终规则

- 固定：`1 PV = ¥12.5` 净营业额。
- PV 和金额均保留两位，使用十进制四舍五入。
- 金额为 source：`pv = round(net_amount / 12.5, 2)`。
- PV 为 source：`net_amount = round(pv * 12.5, 2)`。
- 后端金额以“分”存储和计算，禁止用二进制浮点做金额精确相等判断。
- 后端校验以 `round(net_amount / 12.5, 2) == submitted_pv` 为准，因此 `¥10.01 → 0.80 PV` 合法，不要求反算金额等于 `¥10.01`。
- 回归覆盖 `100 PV ↔ ¥1250.00`、`0.88 PV ↔ ¥11.00`、`¥10.01 → 0.80 PV`、零值、高值和空值。
- 收入模拟公式、Golden Test、财务口径和工作量计数规则未修改。

## 7. 梦想多图最终模型与交互

- 数据模型复用 `dream_files`，一个梦想最多关联 10 个当前账号拥有的 `DREAM_IMAGE` 文件。
- 前端可一次或多次选择图片；每张独立显示上传中/失败状态，失败项可单独重试。
- 新上传但取消或未关联的临时文件调用既有清理机制；删除已有图片在梦想成功保存后清理物理文件，避免保存失败造成数据丢失。
- 排序可通过拖拽或键盘可操作的前移/后移按钮完成，第一张作为封面。
- 详情态提供轮播、上一张/下一张、位置计数和移动端 swipe。
- 后端在事务内验证数量、去重和 ownership，再按请求顺序持久化；第 11 张被拒绝。

## 8. 日历 move/resize 与重复日程策略

- `timeGridWeek` 和 `timeGridDay` 开启事件移动与时长调整，月视图也保持可点击详情。
- 单次日程 move/resize 立即调用更新接口；失败时执行 FullCalendar `revert()` 并展示错误。
- 重复实例 move/resize 不会静默修改整个系列，而是要求选择：`THIS_ONLY`、`THIS_AND_FOLLOWING` 或 `SERIES`。
- `THIS_ONLY` 使用实例原始发生时间创建/更新例外。
- `THIS_AND_FOLLOWING` 从目标实例开始拆分后续规则。
- `SERIES` 以系列根事件为基准应用时间差，避免把系列起点错误替换为当前实例日期。
- 组件测试覆盖成功、rollback 和作用范围选择；Phase 3 集成测试覆盖重复日程作用范围和更新结果。
