# JL团队生意成长管理系统——UI 重构 Phase B 设计说明 V1.0

## 1. Phase B 目标

Phase B 在已经完成的 Phase A App Shell、侧边栏、顶部栏和首页基础上，重构四个核心业务页面：

1. 今日工作
2. 梦想与目标
3. 团队
4. 日历

本阶段仍然属于 UAT 期间的纯前端体验优化。

原则：

- 不修改后端 API 语义；
- 不新增 migration；
- 不修改数据库结构；
- 不修改权限模型；
- 不改变业务统计口径；
- 不删除现有能力；
- 所有原 URL 保持兼容；
- 已通过的自动化测试继续保持通过。

---

# 2. Phase B 内部实施顺序

建议内部拆成四个独立小阶段：

- B1：今日工作
- B2：梦想与目标
- B3：团队
- B4：日历

每个小阶段完成后：

1. 运行相关前端测试；
2. 运行 `git diff --check`；
3. 创建独立 commit；
4. 不要求产品负责人中途验收；
5. 继续下一小阶段。

四个小阶段全部完成后，再执行全量：

```bash
make lint
make test
make build
make check
make test-e2e
git diff --check
```

最后输出统一 Phase B 完成报告。

# 3. B1：今日工作

## 3.1 当前主要问题

当前页面：

- 表单纵向很长；
- 八个顾客行动都使用普通输入框；
- 右侧实时摘要长期占据较大空间；
- 营业额和学习投入被放在同一个传统表单中；
- 高频页面需要较多滚动；
- 手机端不够适合高频触控录入。

## 3.2 重构目标

目标：

> 普通一天的记录尽量在约 1 分钟内完成。

页面结构建议：

```text
今日工作                                      2026-09-16

今日概览
行动 18        学习 75 分钟        120 PV

顾客行动
┌────────────┬────────────┬────────────┬────────────┐
│ 开启对话   │ 深入对话   │ Buffer     │ 分享故事   │
│  −  8  +   │  −  4  +   │  −  2  +   │  −  1  +   │
├────────────┼────────────┼────────────┼────────────┤
│ 筛选       │ 提供机会   │ 会面       │ 顾客跟进   │
│  −  3  +   │  −  2  +   │  −  1  +   │  −  4  +   │
└────────────┴────────────┴────────────┴────────────┘

成长投入
阅读        [ 30 ] 分钟
听音频      [ 45 ] 分钟

营业额
PV          [ 120 ]
净营业额    ¥1,500

备注
[..............................................]

                                      保存今日记录
```

## 3.3 数字步进器

顾客行动字段优先使用步进器：

```text
−   8   +
```

要求：

- 允许点击 `+` / `−`；
- 数值不得小于 0；
- 仍允许直接键盘输入；
- 手机端按钮有足够触控面积；
- 键盘操作和无障碍标签可用；
- 不改变后端字段类型。

## 3.4 日期切换

页面顶部提供紧凑日期导航：

```text
‹    2026-09-16    ›     今天
```

可快速补录前一天或查看历史日期。

继续复用现有历史编辑能力。

## 3.5 摘要

删除长期占据右侧大列的“实时摘要”。

改为顶部紧凑摘要：

- 行动总数；
- 学习分钟；
- PV / 净营业额。

## 3.6 最近记录

最近记录降级为页面底部紧凑区域，可：

- 显示最近 5～7 条；
- 或折叠；
- 点击日期直接编辑。

# 4. B2：梦想与目标

## 4.1 当前主要问题

当前页面把以下内容全部同时展开：

- 新建目标表单；
- 梦想输入；
- 梦想图片；
- 目标地图；
- 目标列表。

导致页面过长，并且最重要的“目标关系图”反而面积不足。

## 4.2 新页面结构

```text
梦想与目标                                      + 新建目标

[目标地图] [目标列表] [梦想板]
```

默认 Tab：

> 目标地图

## 4.3 目标地图

目标地图应该成为主要工作区：

- 尽量使用大画布；
- 支持当前已有节点交互；
- 支持缩放/拖动时保持清晰；
- 点击节点打开右侧详情 Drawer；
- Drawer 显示目标信息、进度、父目标、子目标等；
- 编辑操作从 Drawer 发起；
- 不在画布上长期占用新建表单。

## 4.4 新建目标

点击：

`+ 新建目标`

打开右侧 Drawer。

字段继续使用现有业务字段：

- 目标名称；
- 层级；
- 父目标；
- 开始日期；
- 截止日期；
- 状态；
- 指标；
- 目标值；
- 单位。

手机端 Drawer 变为全屏 Sheet。

## 4.5 目标列表

列表页适合：

- 搜索；
- 按层级筛选；
- 按状态筛选；
- 查看当前进度；
- 编辑。

不要复制一套独立业务逻辑。

## 4.6 梦想板

梦想板改为视觉卡片：

```text
┌─────────────┐
│ 梦想图片     │
│ 梦想标题     │
│ 关联目标 2   │
└─────────────┘
```

顶部：

`+ 新增梦想`

新增/编辑梦想使用 Drawer 或 Modal。

## 4.7 空状态

避免出现占据数百像素高度的大型空状态框。

目标为空时：

- 一段简短说明；
- 一个主按钮；
- 合理的最小高度。

# 5. B3：团队

## 5.1 当前主要问题

当前首屏一半以上空间用于“新增成员表单”，团队关系图被压缩。

团队页面的主要价值应是：

> 看结构，而不是一直看新增表单。

## 5.2 页面结构

```text
团队                               + 新增成员   保存快照

28 位成员     24 活跃     本月 +3

[关系图] [成员列表] [历史快照]

搜索成员……

[大面积关系图]
```

## 5.3 关系图

- 作为默认 Tab；
- 尽量使用大面积工作区；
- 保留当前节点关系；
- 节点信息简洁；
- 点击节点打开右侧详情 Drawer；
- Drawer 中提供编辑成员；
- 关系图区域允许横向/纵向平移；
- 如现有能力支持缩放则保留；
- 避免关系图被表单挤压。

## 5.4 新增 / 编辑成员

`+ 新增成员` 打开 Drawer。

字段继续保持：

- 姓名；
- 上级成员；
- 级别；
- 城市；
- 加入日期；
- 状态；
- 备注。

编辑成员复用相同 Drawer。

## 5.5 成员列表

列表适合：

- 搜索；
- 查看状态；
- 快速编辑；
- 查看上级；
- 查看层级。

不得改变 `member_code` / `parent_member_code` 等现有后端逻辑。

## 5.6 历史快照

单独 Tab：

- 快照日期列表；
- 手动/自动来源；
- captured_late 等已有字段如当前 UI 已显示可继续；
- 选择快照后查看对应团队结构。

## 5.7 手机端

手机关系图空间有限：

- 首先保证可查看；
- 可以支持缩放/拖动；
- 同时提供成员列表作为等价入口；
- 新增/编辑使用全屏 Sheet。

# 6. B4：日历

## 6.1 当前状态

日历现有布局方向整体可保留，不做大规模业务重写。

主要问题：

- 页面外围层级偏重；
- 月历下方长期存在大型“已加载日程”区域；
- 页面纵向过长。

## 6.2 页面结构

```text
日历                                         + 新建日程

‹   今天   ›                2026年9月          月 | 周 | 日

┌───────────────────────────────────────────────┐
│                                               │
│                    日历                       │
│                                               │
└───────────────────────────────────────────────┘
```

## 6.3 日期详情

点击某一天：

- 桌面右侧打开 Day Detail Drawer / Panel；
- 显示当日日程；
- 提供 `+ 新建日程`；
- 点击事件编辑。

不要再在月历底部长期开一个大型“已加载日程”卡片。

## 6.4 新建 / 编辑日程

使用现有日程创建能力。

可以继续使用：

- Modal；
- Drawer；

但交互风格应和其他页面统一。

必须保留：

- 普通日程；
- 全天；
- 重复日程；
- 单次修改；
- 本次及以后；
- 整个系列；
- 邮件邀请；
- ICS；
- 时区逻辑。

## 6.5 月 / 周 / 日视图

保持已有功能。

不为了布局重构重新实现日历算法。

# 7. 通用 Drawer / Sheet 规范

Phase B 建议建立统一的 Drawer / Sheet 组件模式。

桌面：

- 从右侧滑出；
- 宽度根据表单复杂度约 420～560px；
- 头部固定；
- 底部操作区固定；
- 中间内容可滚动。

手机：

- 使用全屏或接近全屏 Sheet；
- 主操作按钮易触控；
- 不出现横向溢出。

适用：

- 新建目标；
- 编辑目标；
- 新增成员；
- 编辑成员；
- 新增梦想；
- 日程详情/编辑。

# 8. 状态和 URL

Phase B 可以使用前端 URL query / hash 表达 Tab，例如：

```text
/goals?tab=map
/goals?tab=list
/team?tab=tree
/team?tab=snapshots
```

但必须：

- 保持已有主路由兼容；
- 不要求后端修改；
- 浏览器刷新后保持合理页面状态。

---

# 9. 可访问性

按钮和步进器需要：

- 正确 button 语义；
- aria-label；
- 键盘可操作；
- focus 状态清楚。

抽屉打开时：

- focus trap；
- Escape 可关闭；
- 关闭后焦点返回触发按钮。

# 10. 测试重点

必须验证：

### 今日工作
- 步进器不会产生负数；
- 输入值与保存一致；
- PV/金额转换不变；
- 历史日期编辑不变。

### 梦想与目标
- Tab 切换；
- Drawer；
- 父子目标；
- 梦想图片；
- 原业务 URL。

### 团队
- 关系图仍正确；
- 新增/编辑；
- 成员列表；
- 快照；
- 权限。

### 日历
- 月/周/日；
- 新建；
- 重复规则；
- 点击日期详情；
- 移动端。

# 11. Phase B 验收标准

完成后：

- 今日工作明显比旧版更适合高频录入；
- 目标地图成为梦想与目标页主视图；
- 团队关系图成为团队页主视图；
- 日历无需向下滚很长才能看日程详情；
- 大型表单默认不再长期占首屏；
- Desktop / Mobile 均可用；
- 不修改后端业务规则；
- 所有自动化测试通过。
