# 2. 开始前的 Git 安全检查

当前上一次报告显示工作区存在大量 Phase A 之外的历史未提交变更。

在修改任何 Phase B 文件前：

1. 执行：
   ```bash
   git status --short
   git log --oneline --decorate -8
   ```
2. 识别当前所有未提交文件来源。
3. 不得删除、覆盖或偷偷吸收这些历史变更。
4. 如果这些变更是产品负责人希望保留的既有 UAT/视觉优化：
   - 先建立一个明确的 checkpoint commit；
   - commit message 建议：
     `chore: checkpoint pre-phase-b working tree`
5. 如果无法确认某些变更是否应该保留：
   - 停止；
   - 报告文件列表；
   - 不开始 Phase B。

Phase B 必须从一个可解释、可回滚的 Git 状态开始。

# 3. 功能冻结

本次禁止：

- 后端 API 变更；
- migration；
- OpenAPI 业务合约变更；
- 权限规则变更；
- 收入公式变更；
- 导入规则变更；
- 数据统计口径变更；
- 新业务模块；
- 删除原功能。

若纯前端无法完成某项要求，停止并报告，不擅自扩展范围。

## B2

---

# 5. B1 今日工作

按设计文件实现：

- 页面顶部紧凑日期导航；
- 顾客行动使用适合高频操作的数字步进器；
- 八个行动在桌面形成清晰网格；
- 学习投入单独分区；
- 营业额单独分区；
- 备注单独分区；
- 实时摘要压缩成顶部紧凑指标；
- 最近记录降级到底部；
- 手机端适合单手触控。

必须保留：

- 历史日期补录；
- 修改；
- 删除/现有编辑语义；
- PV/净营业额转换；
- 学习时间；
- 所有后端字段。

不得让步进器阻止用户直接键盘输入数值。

---

# 6. B2 梦想与目标

实现：

```text
[目标地图] [目标列表] [梦想板]
```

要求：

- 默认进入目标地图；
- 目标地图获得主视觉空间；
- 新建目标使用右侧 Drawer；
- 点击目标节点使用详情 Drawer；
- 编辑目标复用 Drawer；
- 目标列表作为独立 Tab；
- 梦想板使用视觉卡片；
- 新建/编辑梦想使用 Drawer 或 Modal；
- 空状态缩小，不使用大面积空白框。

必须保留：

- 父子目标；
- 目标层级；
- 指标目标；
- 自动完成度；
- 梦想图片；
- 梦想与目标关联。

---

# 7. B3 团队

实现：

```text
[关系图] [成员列表] [历史快照]
```

要求：

- 默认关系图；
- 关系图成为主工作区；
- 新增成员使用 Drawer；
- 点击节点查看详情并可编辑；
- 成员列表支持原有核心操作；
- 历史快照独立 Tab；
- 保存快照按钮位于页面级操作区；
- 搜索成员入口保留。

必须保留：

- 当前组织树逻辑；
- `member_code`；
- `parent_member_code`；
- 快照；
- captured_late 等现有业务行为；
- 现有权限。

不要为了 UI 重构改团队数据结构。

---

# 8. B4 日历

保持现有日历核心组件和业务逻辑。

主要调整：

- 月/周/日历成为页面主区域；
- 删除长期位于日历下方的大型“已加载日程”区；
- 点击日期后打开右侧当日详情 Panel/Drawer；
- 当日详情中显示日程和新增入口；
- 新建日程操作保持清晰；
- 事件编辑继续使用现有能力。

必须回归：

- 普通事件；
- 全天事件；
- 重复日程；
- 单次修改；
- 本次及以后；
- 整个系列；
- 邮件邀请；
- ICS；
- 时区；
- 月/周/日。

---

# 9. 通用 UI

如果当前项目没有通用 Drawer/Sheet，可增加纯前端通用组件。

要求：

- Desktop 右侧 Drawer；
- Mobile 全屏 Sheet；
- focus trap；
- Escape 关闭；
- 关闭后焦点恢复；
- 固定标题区和操作区；
- 表单主体可滚动。

优先复用现有设计系统和依赖，不无故引入大型新 UI 库。
