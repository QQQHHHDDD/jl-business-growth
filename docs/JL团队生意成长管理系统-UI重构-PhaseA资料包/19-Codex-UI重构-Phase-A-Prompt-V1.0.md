# JL团队生意成长管理系统——Codex UI 重构 Phase A Prompt V1.0

## 1. 任务背景

当前系统已经完成第7阶段自动化综合测试，并进入 UAT。

产品负责人确认：

- 当前侧边栏一级菜单过多；
- 页面布局过于拥挤；
- 页面标题存在重复；
- 首页卡片过多、视觉权重相同。

本次执行 **UI 重构 Phase A**。

Phase A 只允许修改：

1. App Shell；
2. 桌面侧边栏；
3. 移动端导航壳；
4. 顶部栏；
5. 页面通用容器；
6. 首页 Dashboard。

不要提前重构其他业务页面。

## 2. 开始前

先不要修改代码。

完整阅读：

- 根目录 `AGENTS.md`
- 当前生效设计文档
- `docs/18-V1-UIUX信息架构重构设计-V1.0.md`
- 当前 App Shell
- 当前路由
- 当前 Dashboard
- 当前移动端导航
- 当前全局搜索
- 当前账号切换/登出逻辑
- 当前前端测试和 Playwright

先输出简短实施计划，说明：

- 将修改哪些组件；
- 如何保持路由兼容；
- 如何复用现有搜索和账号能力；
- 如何避免后端改动；
- 如何保证移动端不退化。

确认可纯前端完成后再开始修改。

如果发现必须修改 API、数据库或业务规则，停止并报告。

## 3. 功能冻结

禁止：

- 新增后端 API；
- 新增 migration；
- 修改 OpenAPI 业务合约；
- 修改权限；
- 修改收入公式；
- 修改导入导出规则；
- 修改业务统计口径；
- 删除现有功能。

允许：

- 重构 React 组件；
- 重构 CSS/Tailwind；
- 增加通用 Layout 组件；
- 增加 Accordion/NavGroup；
- 增加 Account Menu；
- 增加 Sidebar Collapse；
- 调整 Dashboard 页面组合；
- 使用现有 API 重新组织 Dashboard 数据；
- 调整前端展示，但保持现有 URL 可访问。

## 4. 新侧边栏

实现：

```text
首页

▸ 规划与执行
   梦想与目标
   日历
   今日工作

▸ 经营管理
   营业额
   团队
   财务
   收入模拟

▸ 成长与复盘
   学习中心
   复盘
   数据统计

▸ 系统工具
   导入 / 导出
   设置
```

要求：

- 全局搜索从侧栏移除；
- 只展开当前路由所属分类；
- 点击其他分类时自动折叠上一分类；
- 当前二级路由有清晰 active 状态；
- 刷新后根据 URL 自动展开；
- 桌面侧栏约 220px；
- 支持收起为约 64px 图标栏；
- 收起状态只允许前端保存；
- 收起后有 Tooltip；
- 不破坏普通用户/管理员角色导航差异。

管理员后台保持独立管理导航，只统一视觉。

## 5. 顶部栏

重构为：

```text
面包屑 / 页面位置              全局搜索              账号菜单
```

要求：

- 删除固定“退出登录”按钮；
- 账号菜单复用现有账号切换和登出；
- 至少包含：切换账号、账号设置、退出登录；
- 不再重复“个人工作台 + 页面名 + 页面名”。

全局搜索：

- 顶部提供常驻入口；
- Phase A 不重写后端搜索；
- 可以跳转现有搜索页；
- 或使用轻量浮层调用现有搜索逻辑；
- 不得改变搜索 API。

## 6. 页面通用容器

建立可复用页面框架，例如：

- AppShell
- Sidebar
- SidebarGroup
- Topbar
- AccountMenu
- PageContainer
- PageHeader

具体文件名按当前代码决定。

普通页面：

- 最大宽度约 1360px；
- 居中；
- 桌面 padding 24～32px。

Phase A 暂不重构目标图、团队图、日历等业务页内部。

## 7. Dashboard 重构

### A. Greeting
显示：
- 用户称呼；
- 当前日期。

### B. 第一行

今日计划：
- 使用现有 Calendar/Dashboard 数据；
- 展示最近几条今日事项；
- 提供进入日历入口。

当前目标：
- 展示 1～3 个重点进行中目标；
- 显示真实完成度；
- 提供进入目标页入口。

### C. 本周经营

紧凑展示至少：

- 开启；
- 深入；
- Buffer；
- 会面；
- PV。

允许使用现有 analytics endpoint 展示简单趋势。

不得新增后端 API。

### D. 团队 / 学习 / 财务摘要

三块紧凑摘要：

- 团队；
- 学习；
- 财务。

只使用真实已有数据。

### E. 删除/合并

首页移除：

- 浏览器账号大卡片；
- 三张大尺寸快速入口卡；
- 与 KPI 重复的营业额节奏大卡；
- 梦想数量独立顶级 KPI。

不得删除对应业务能力。

## 8. 视觉要求

保留当前青绿色品牌色。

要求：

- 背景极浅灰；
- 减少 Card；
- 减少大面积空状态框；
- 标题层级统一；
- 不使用花哨渐变；
- 企业级 SaaS 风格；
- 优先清晰和长期使用。

## 9. 移动端

必须保持移动端可用。

保留现有高频底部导航思路：

- 首页
- 今日工作
- 日历
- 设置

完整菜单通过 Drawer / Sheet 访问。

桌面折叠侧栏逻辑不要直接照搬到手机。

## 10. 测试

完成后至少执行：

```bash
make lint
make test
make build
make check
make test-e2e
git diff --check
```

必须增加/更新测试覆盖：

- 新侧栏分组；
- 当前路由自动展开；
- 点击分类折叠；
- 侧栏收起；
- Search 入口；
- Account Menu；
- Dashboard 主要真实数据；
- 普通用户导航；
- Admin 导航；
- 移动端 Drawer / bottom nav。

不要删除原有权限或路由测试。

## 11. 人工验收

完成后启动内网环境，并提供局域网地址。

让产品负责人重点检查：

- 侧栏是否明显更清楚；
- 首页是否明显不拥挤；
- 页面标题是否简洁；
- 搜索和账号入口是否自然；
- 侧栏收起是否好用；
- 手机导航是否正常。

## 12. Git 与结束

本次只完成 Phase A。

不要自动进入 Phase B。

完成后：

1. 提交一个独立 UI Phase A commit；
2. 输出《UI 重构 Phase A 完成报告》；
3. 报告修改文件、组件结构、路由兼容、Dashboard、Desktop/Mobile、测试结果、commit、git status 和已知问题；
4. 停止，等待产品负责人验收。
