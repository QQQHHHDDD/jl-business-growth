# JL团队生意成长管理系统——V1 UI/UX 信息架构重构设计 V1.0

## 1. 文档目的

本文件用于指导 JL团队生意成长管理系统在 UAT 阶段进行一次**不改变业务规则、不改变后端 API、不改变数据库结构**的前端信息架构与页面布局重构。

本次重构的目标不是“换皮”，而是解决三个核心问题：

1. 一级侧边栏功能项过多，用户难以形成清晰的业务心智模型；
2. 页面普遍采用“大标题 + 多卡片 + 大表单 + 大空状态”的同质化布局，信息层级不足；
3. 很多页面同时展示录入、查看、历史和辅助信息，高频操作不够直接。

必须保持：

- 现有业务功能不减少；
- 后端接口行为不变；
- 数据库不变；
- 权限模型不变；
- 现有路由尽量兼容；
- 已通过的自动化测试不得被破坏。

## 2. 设计原则

- 从“功能清单”转向“业务流程导航”；
- 高频操作优先：首页、今日工作、日历；
- 查看优先，录入按需出现；
- 不滥用 Card；
- 目标图、团队图、日历、数据图表优先获得空间。

## 3. 新的信息架构

### 一级导航

```text
首页

▸ 规划与执行
▸ 经营管理
▸ 成长与复盘
▸ 系统工具
```

### 二级导航

规划与执行：
- 梦想与目标
- 日历
- 今日工作

经营管理：
- 营业额
- 团队
- 财务
- 收入模拟

成长与复盘：
- 学习中心
- 复盘
- 数据统计

系统工具：
- 导入 / 导出
- 设置

### 全局搜索

全局搜索从侧边栏移除，移到顶部栏。Phase A 不改变后端搜索接口。

## 4. 侧边栏行为

- 展开宽度建议约 220px；
- 收起宽度建议约 64px；
- 首页始终直接可见；
- 默认只展开当前路由所属分类；
- 点击其他分类时自动收起上一分类；
- 刷新后根据路由自动展开正确分类；
- 收起后仅显示图标并提供 Tooltip；
- 不新增后端用户设置字段。

## 5. 顶部栏

建议结构：

```text
规划与执行 / 今日工作       🔍 全局搜索       qlanhaodong ▾
```

顶部栏承担：

- 面包屑；
- 全局搜索；
- 当前账号；
- 账号菜单。

账号菜单至少包含：

- 切换账号；
- 账号设置；
- 退出登录。

删除长期固定的“退出登录”按钮，并压缩重复页面标题。

## 6. 页面容器

普通页面：

- 最大宽度建议约 1360px；
- 居中；
- 桌面横向 padding 24～32px。

大画布页面允许更宽：

- 目标地图；
- 团队关系图；
- 日历；
- 数据统计。

每页只保留一组主标题：

```text
页面名称                              主要操作
一句简短说明
```

## 7. 视觉系统

继续保留当前青绿色主色。

建议：

- 页面背景：极浅灰，如 #F6F8FA；
- 卡片圆角：8～12px；
- 卡片边框：浅灰；
- 阴影轻量或不用；
- 页面纵向间距：24～32px；
- 卡片内部 padding：20～24px；
- 页面主标题：24～28px；
- 区块标题：16～18px；
- 危险操作使用红色；
- 次级按钮使用白底灰边。

避免所有内容都套 Card。

## 8. 首页重构

首页只回答：

1. 今天要做什么？
2. 本周 / 本月做得怎么样？
3. 当前目标进展如何？

建议布局：

```text
下午好，qlanhaodong                         2026年9月16日

┌─────────────────────┐  ┌─────────────────────┐
│ 今日计划             │  │ 当前目标             │
│ 14:00 PHP            │  │ 本月会面  6 / 8      │
│ 20:00 团队会议       │  │ 本月PV 1600 / 2500   │
│ + 添加日程           │  │ 查看全部目标 →       │
└─────────────────────┘  └─────────────────────┘

本周经营
开启 42   深入 16   Buffer 8   会面 3   PV 1200

[工作量趋势图]

┌──────────────────┐ ┌──────────────────┐ ┌──────────────────┐
│ 团队              │ │ 学习              │ │ 财务              │
│ 27 人 / 本月 +3   │ │ 本周 185 分钟     │ │ 本月净现金流       │
└──────────────────┘ └──────────────────┘ └──────────────────┘
```

首页移除：

- 浏览器账号大卡片；
- 三张大尺寸快速入口卡；
- 与 KPI 重复的营业额节奏大卡；
- 梦想数量独立顶级 KPI。

## 9. 今日工作

目标：正常情况下约 1 分钟内完成录入。

建议将普通数字输入改为更适合高频录入的步进器：

```text
−   8   +
```

分区：

- 顾客行动：开启、深入、Buffer、分享、筛选、提供机会、会面、顾客跟进；
- 成长投入：阅读分钟、音频分钟；
- 营业额：PV、净营业额；
- 备注。

右侧长期占据空间的实时摘要应压缩。

## 10. 梦想与目标

建议：

```text
梦想与目标                          + 新建目标

[目标地图] [目标列表] [梦想板]
```

- 目标地图成为主视图；
- 点击目标节点打开右侧详情；
- 新建目标使用 Drawer；
- 梦想板单独成为 Tab。

## 11. 日历

整体方向保留。

优化：

- 删除重复标题层；
- 压缩外围 Card；
- 点击日期后在右侧显示当日日程；
- 不长期展示一个大面积“已加载日程”区。

## 12. 营业额

简化为：

- 今日营业额录入；
- 本月累计；
- 趋势；
- 最近记录。

`1 PV = ¥12.5` 作为辅助信息，不独占右侧大卡。

## 13. 团队

默认以关系图为主：

```text
团队                            + 新增成员   保存快照

28 位成员   24 活跃   本月 +3

[关系图] [成员列表] [历史快照]

搜索成员……

[大面积团队关系图]
```

新增 / 编辑成员使用 Drawer。

## 14. 学习中心

从“录入表单页”改为“内容管理页”。

```text
学习中心                              + 新增学习

本周 185 分钟   3 项进行中   2 项完成

[学习项目] [附件库]

搜索……
```

新增学习项目使用 Drawer。

## 15. 财务

财务拆分为：

```text
财务

[总览] [流水] [预算] [资金快照]
```

总览：
- 本月收入；
- 本月支出；
- 净现金流；
- 现金流趋势；
- 支出分类。

流水：
- 列表；
- 新增流水 Drawer。

预算：
- 月预算；
- 已用；
- 剩余；
- 历史预算。

资金快照：
- 储蓄；
- 应急资金；
- 历史快照。

## 16. 收入模拟

收入模拟采用“计算工作台”：

```text
收入模拟                     [当前方案 ▼]   保存方案

① 基础数据
② 市场结构
③ 奖励条件

                                   [计算收入]
```

结果区域建议右侧 sticky。

内部 Tab：

- 模拟器；
- 保存方案；
- 方案比较。

不得改变现有收入公式。

## 17. 复盘

保留：

```text
[每日复盘] [每周复盘] [每月复盘]
```

周期指标摘要和复盘文本放在同一个主要工作区。

## 18. 数据统计

建议：

```text
数据统计

[工作量] [营业额] [目标] [团队] [财务]

本周 | 本月 | 本年 | 自定义
```

单次只展示一个领域的核心指标、趋势和明细。

## 19. 全局搜索

侧栏不再有独立全局搜索入口。

顶部提供搜索入口，完整搜索结果页保留原路由。

## 20. 导入导出与设置

归入：

```text
系统工具
├── 导入 / 导出
└── 设置
```

只做视觉统一，不改业务逻辑。

## 21. 移动端

- 保留高频底部导航：首页、今日工作、日历、设置；
- 完整功能通过 Drawer / Sheet 访问；
- 表单 Drawer 在手机上变为全屏 Sheet；
- 目标/团队关系图需要支持缩放、滚动或列表替代；
- 今日工作步进器适合触控。

## 22. 分阶段实施

### Phase A
只做：
- App Shell；
- 侧边栏；
- 顶部栏；
- 页面容器；
- 首页。

### Phase B
做：
- 今日工作；
- 梦想与目标；
- 团队；
- 日历。

### Phase C
做：
- 财务；
- 学习中心；
- 收入模拟；
- 复盘；
- 数据统计。

### Phase D
做：
- 导入导出；
- 设置；
- 搜索体验；
- 响应式统一；
- 视觉一致性；
- UAT 回归。

## 23. 非目标

本次 UI/UX 重构不得：

- 修改收入模拟公式；
- 修改数据库 schema；
- 修改权限模型；
- 修改账户删除规则；
- 修改导入幂等规则；
- 修改后端 API 语义；
- 新增业务模块；
- 删除已有 V1 功能；
- 改变统计口径。

## 24. Phase A 验收标准

至少满足：

- 侧边栏只保留 4 个业务分类 + 首页；
- 子导航可展开/折叠；
- 当前分类自动展开；
- 侧栏支持收起；
- 全局搜索移到顶部；
- 账号操作进入顶部账号菜单；
- 页面标题不再重复；
- 首页明显减少卡片数量；
- 首页可以快速看到今日计划、目标、本周经营和团队/学习/财务摘要；
- 桌面端与手机端导航不破坏；
- 原路由仍可访问；
- 原业务功能不丢失；
- 所有既有测试继续通过。
