## 1. 总体架构

采用：

> 响应式 Web + 前后端分离 + Go 模块化单体 + PostgreSQL 单库 + 本地文件存储。

```text
用户浏览器
    │ HTTPS
    ▼
  Nginx
  ├───────────────→ React + TypeScript + Vite
  └── /api/* ─────→ Go / Echo
                       │
             ┌─────────┼─────────┐
             ▼         ▼         ▼
        PostgreSQL   Files      SMTP
```

生产环境前端和 API 使用同一域名，API 固定在 `/api/*`，避免不必要的跨域复杂度。

## 3. 账号角色

- `USER`：普通用户；
- `ADMIN`：普通管理员；
- `SUPER_ADMIN`：固定超级管理员。

超级管理员与普通管理员共用同一管理员端；只有超级管理员能看到并操作管理员账号管理区域。

## 4. 前端总体导航

普通用户端：

- 首页；
- 梦想与目标；
- 日历；
- 每日工作量；
- 营业额；
- 团队；
- 学习中心；

## 5. 核心数据原则

### 单一事实源

- 读书/听音频时间以学习活动记录为事实源；
- 每日工作量页面只是另一个录入和展示入口；
- 营业额只有一份每日数据，多页面共享；
- 目标实际进度来自业务数据聚合，不人工维护第二份“实际值”。

### 用户隔离

所有普通用户业务数据必须带 `user_id`，后端每次查询都以当前认证用户作为强制条件。

## 6. 文件总体设计

允许文件：PDF、TXT、Markdown、JPG/PNG/WebP。

文件保存在 Web 根目录之外。数据库保存元数据，文件内容通过鉴权 API 返回。

V1 接受当前实现采用 `FILE_ROOT` 下的 UUID 扁平文件存储，不强制按用户创建物理子目录。用户隔离由数据库中的文件归属关系和后端鉴权保证。后续只有在文件规模或运维需求明显增长时，才考虑迁移为用户分层目录或对象存储。

预览：

- PDF：浏览器内嵌；
- TXT：安全纯文本查看；
- Markdown：安全 Markdown 渲染；
- 图片：内嵌查看。

不支持 DOCX；不提取正文；不做 OCR；搜索不读取文件内部内容。

## 7. 日历总体设计

使用“主事件 + 重复规则 + 例外实例”模型。

支持：

- 单次；
- 每天；
- 每周；
- 每月；
- 每年；
- 每 N 天/周/月；
- 单实例修改；
- 本实例及以后；
- 整个系列。

邮件使用 ICS 标准邀请，邮件模块和日历模块解耦。

## 8. 目标与团队可视化

目标和团队都采用节点/连线式可视化能力，重点保证：

- 美观；
- 缩放/平移；
- 层级清晰；
- 进度和状态一眼可见；
- 移动端提供简化列表作为替代视图。

目标额外提供时间线/进度视图，团队提供历史快照切换。

## 9. 搜索

V1 使用 PostgreSQL 完成模糊搜索，搜索系统结构化文本和用户手工录入文本，不搜索附件文件正文。

## 10. 收入模拟

计算引擎完全放在 Go 后端。

```text
输入 → 参数校验 → 规则版本 → 计算引擎 → 结果 → 可选保存方案
```

保留 Excel 兼容结果字段，同时在产品层将年度/一次性奖励单独展示。

## 11. 时区

- 时间戳使用 PostgreSQL `timestamptz`；
- 用户保存 IANA timezone；
- 每日工作量、营业额、复盘等保存独立业务日期；
- 重复日程按照事件时区保持当地墙钟时间。

## 13. 开发、验收与生产拓扑

系统采用同一代码库、三类运行环境。

### 13.1 Development

```text
内网浏览器
  │ http://LAN-IP:5173
  ▼
Vite Dev Server
  ├── 前端 HMR
  └── /api/* proxy ──→ 127.0.0.1:8080 Go API
                           │
                           ├── PostgreSQL: jl_business_dev
                           ├── .local/files
                           └── .local/mail-outbox
```

Go API 不需要直接暴露到内网，只监听 `127.0.0.1`，由 Vite 代理访问。

### 13.2 Test

自动测试使用独立 `jl_business_test` 数据库和临时文件目录，不复用开发数据。

### 13.3 Production

```text
Internet
  │ HTTPS
  ▼
Nginx
  ├── React dist
  └── /api/* ──→ 127.0.0.1:8080 jl-business-api
                      │
                      ├── PostgreSQL production DB
                      ├── /var/lib/jl-business-growth/files
                      └── SMTP
```

开发环境不要求域名或 HTTPS；生产环境必须使用域名和 HTTPS。

## 14. 发布架构

Git 仓库是唯一源码来源。生产环境只接收经过测试的版本化构建产物和 migration，不在生产服务器进行日常 Vibe Coding。

发布包至少包含：

- `jl-business-api` Go 二进制；
- `frontend-dist/`；
- 数据库 migration；
- 部署配置模板版本；
- 版本信息。

生产密钥与配置永远保留在云服务器，不放入 Git，也不提供给 Codex 开发会话。


## 实现对齐补充（Phase 6 收口）

以下工程实现被正式接受为 V1 技术实现，不视为产品偏离：

- 前端/后端目录可以按当前代码集中组织，不要求为了与示例目录完全一致而重构；
- 收入模拟规则集中在后端 Go 计算引擎中，可使用版本化常量/映射，只要规则不散落前端、具有 `income-v1-excel-compatible` 等明确版本标识并受 Golden Test 保护；
- 固定模板 XLSX 可使用项目自有的最小读写实现，不要求引入通用 Excel 库；
- 文件物理目录采用 UUID 扁平存储是 V1 可接受方案。

以上接受不改变业务层面的硬性要求，例如用户隔离、梦想图片关联、知识附件关联、团队快照时区、删除账户物理文件清理、可恢复导出和导入幂等。
