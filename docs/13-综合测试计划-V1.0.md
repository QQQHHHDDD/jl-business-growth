# JL团队生意成长管理系统——第7阶段综合测试计划 V1.0

## 1. 目的与基线

本阶段用于验证 Phase 0～6 与 V1 收口完成后的系统是否能够作为一个完整产品运行，而不是继续新增功能。

测试基线：
- 分支：`master`
- 基线 commit：`86c87cb fix: close V1 release blockers`
- Phase 0～6：已完成
- P0-01～P0-11：已完成
- 当前阶段：第7阶段综合测试
- 生产环境：暂不部署

目标：验证完整业务闭环、权限与数据隔离、导入导出、金额与收入计算、文件与账户删除、团队时区、桌面/手机体验，以及未来 10～50 用户规模下的基础性能。

## 2. 测试环境

继续使用现有内网 Ubuntu 服务器：
- PostgreSQL 开发库与独立测试库
- Go 1.27 项目工具链
- Node.js/npm 项目要求版本
- React/Vite 前端
- Go API
- 本地文件存储
- 本地 mail outbox
- 不配置正式 SMTP
- 不使用生产数据库、生产域名和生产密钥

## 3. 原则

1. **功能冻结**：不新增 V1 功能，只修 Bug、权限问题、数据一致性问题、严重 UX 和发布阻塞项。
2. **自动化测试数据与 UAT 分离**：自动化只用测试数据；人工 UAT 可使用少量真实/脱敏业务数据。
3. **邮件先本地验证**：验证 ICS 和邮件内容；真实 SMTP 留到生产部署阶段。
4. **所有修复都必须有回归测试**。
5. **P0/P1 未清零不得进入生产发布**。

## 4. 综合测试范围

### 4.1 认证与权限
- 邀请码注册、登录、登出、修改密码、管理员重置密码
- Session、CSRF、Origin
- 多账号快速切换
- Admin / Super Admin 权限
- 禁用、恢复、用户主动删除、管理员删除
- User A 不得访问 User B 任何业务数据或文件

### 4.2 首页
验证真实聚合：
- 今日/本周工作量
- 本月营业额
- 当前目标
- 近期日程
- 团队摘要
- 学习摘要
- 财务摘要

### 4.3 梦想与目标
- 梦想图片上传、替换、解除、删除清理
- 梦想关联目标
- 父子目标与数字目标
- 自动完成度
- 关系图和移动端可读性

### 4.4 工作量与营业额
- 新建、修改、补录、删除
- 五层计数规则
- 顾客跟进、读书、听音频
- `1 PV = ¥12.5` 双向换算
- 周/月/年统计

### 4.5 日历
- 日/周/月视图
- 全天与普通日程
- 重复日程
- 修改单次 / 本次及以后 / 整系列
- ICS、mail outbox
- 时区、跨日、跨月、DST

### 4.6 团队
- member_code / parent_member_code
- 三层以上结构
- 手动/自动快照
- 用户 IANA 时区
- 延迟补跑与 `captured_late`
- 幂等与历史快照

### 4.7 知识与附件
- PDF/TXT/Markdown/图片上传与预览
- 知识条目关联/解除附件
- 权限隔离
- 标签、笔记、理解、行动项、学习进度

### 4.8 财务
- 分类、收入、支出、预算、快照、储蓄、应急资金
- 十进制字符串 API 与整数分内部计算
- 小数舍入
- 导入、导出、分析

### 4.9 收入模拟
使用 Golden Test 和原 Excel 逐项核对：
- 个人营业额奖金
- 6% 优惠券
- 差额奖金
- 绩优营销之星月度奖励
- 年度成长奖励
- 红宝石奖金
- 基础/精英骨干奖金
- 双年奖金
- 月度收入、一次性奖励、合计收入

同时验证方案保存、复制、比较、删除和规则版本。

### 4.10 分析
验证工作量、营业额、目标、财务、团队的真实数据分析，以及空状态和移动端可读性。图表库不做硬性要求。

### 4.11 复盘与搜索
- 日/周/月复盘唯一性与可修改
- 数据摘要正确
- 模糊搜索：目标、日历、团队、知识、笔记

### 4.12 导入规则
- 工作量：同日 upsert，预览提示
- 营业额：同日 upsert，预览提示
- 团队：member_code upsert，parent_member_code 恢复层级
- 财务：重复指纹默认 skip
- 已 COMMITTED 任务：禁止再次提交
- 相同 SHA-256 文件：提示历史导入/上传记录
- 分类、父节点、日期、金额、PV 等错误尽量在预览阶段阻断

### 4.13 导出与恢复
重点验证：
1. 导出三层 TEAM；
2. 清空测试账号团队；
3. 重新导入；
4. 对比层级；
5. 确认 member_code 与 parent_member_code 完整恢复。

完整账户 ZIP 必须包含结构化数据、图片和文档。

### 4.14 账户删除
用户自删与管理员删除必须统一验证：
- Session 失效
- 数据库数据删除
- 物理文件删除
- 删除失败记录与重试
- DELETING 状态
- 删除中的账号不可继续写入

## 5. 故障测试

至少覆盖：
- PostgreSQL 暂停
- API 重启
- Session 过期
- 网络中断
- 邮件发送失败
- 非法/超大文件
- 重复提交
- 非法金额、日期、PV
- 重复 member_code
- parent_member_code 不存在
- 文件丢失/清理失败

要求：不破坏已有数据，不产生静默重复数据，错误提示可理解。

## 6. 基础性能测试

目标不是极限压测，而是验证 10～50 用户规模无明显性能问题。

模拟 50 用户执行：
- 登录
- Dashboard
- 工作量查询/写入
- 营业额查询
- 分析查询
- 搜索

记录：
- 请求总数
- 成功率/5xx
- P50/P95
- CPU/内存
- PostgreSQL 连接数
- 慢查询和锁等待

通过要求：无大量 5xx、无连接耗尽、无明显内存持续增长、常规接口交互可接受。

## 7. 浏览器与设备

最低人工验收：
- 桌面：Chrome 或 Edge 至少一种
- 手机：用户实际现代浏览器

手机重点：首页、今日工作量、日历、目标、团队查看、学习、设置、账号切换。

## 8. UAT

自动化综合测试通过后，由产品负责人用少量真实/脱敏数据连续使用 3～7 天，重点判断：
- 是否愿意每天打开
- 工作量是否约 1 分钟可录完
- 首页是否有价值
- 团队/目标图是否易读
- 财务是否易录
- 收入模拟是否可信
- 搜索是否方便
- 手机端高频操作是否可接受

## 9. 缺陷分级

- **P0**：数据丢失、越权、敏感信息泄露、数据库损坏、金额/收入关键计算错误、核心系统不可用。必须立即修复。
- **P1**：核心流程无法完成、导入产生错误数据、团队结构损坏、文件权限错误、主要移动流程不可用。V1 发布前必须修复。
- **P2**：明显 UX 或非核心功能问题。评审后决定 V1 或 V1.0.1。
- **P3**：优化建议、视觉细节。后续版本。

## 10. 退出标准

必须同时满足：
- P0 = 0
- P1 = 0
- 关键 P2 已评审
- `make check` 通过
- 集成测试通过
- E2E 通过
- 收入 Golden Test 通过
- 权限专项通过
- 导入导出专项通过
- 删除专项通过
- 50 用户基础性能测试无明显异常
- UAT 完成
- 测试报告完成
- 所有修复进入 Git
- 工作区干净

通过后进入：**V1 Release Candidate / 生产部署演练**。
