## 真实复现与诊断

### 复现方式

在真实 Chromium production preview 中，使用真实测试账号，从注册后首次进入工作台开始，通过左侧侧边栏连续执行 5 轮：

```text
首页 → 今日工作 → 日历 → 梦想与目标 → 团队 → 财务
→ 学习中心 → 复盘 → 数据统计 → 导入/导出 → 设置 → 首页
```

每次切换在点击前启动 12 个连续 `requestAnimationFrame` 采样，并记录 PageContainer 的 child count、top/left/width/height、PageHeader top、document scrollWidth/clientWidth、scrollY；同时记录资源条目、console/pageerror 和 Shell DOM identity。

### 真实结论

修复前共观察 5 轮、55 次跨路由切换：

- App Shell、Sidebar、Topbar、PageContainer 的 DOM identity 全部保持；不是 Shell 或 Sidebar/Topbar remount。
- PageContainer child count 始终大于 0，PageHeader 的 `h1` 缺失帧为 0；route outlet 没有先变成空节点。
- 没有发现 React key 导致的页面外层强制 remount。
- `scrollWidth=1265`、`clientWidth=1280`、`scrollY` 在采样中稳定；没有 scrollbar gutter 或横向溢出跳变。
- 首次进入页面时，确实出现了“旧页面标题 → 新页面 PageHeader + 页面 LoadingState/Suspense fallback → 真实页面”的主体替换。典型采样为：
  - 今日工作：PageContainer `895 → 1804.39`，出现“正在加载工作量记录”；
  - 日历：`656 → 1604.39`，出现“正在加载日历”；
  - 梦想与目标：`656 → 922.78`，出现 `PageLoadingState`；
  - 团队：首次进入加载团队 chunk 和成员/快照请求。
  高度没有塌到 0，但主体内容在短时间内由上一页切换到 loading 再切换到真实内容，形成肉眼可见闪动。
- 首次进入的真实资源链路包含 `calendar-page-*.js`、`goals-page-*.js`、`team-page-*.js`；目标页首次进入还加载了拆分 CSS chunk。后续切换不再重复加载这些 lazy JS chunk。
- 其它页面的动态资源主要是该页面自己的 API fetch；未发现字体、图标或全局 CSS 在每次路由切换时重新加载。
- React Query 的全局 `placeholderData(previousData)` 是全局配置，但完全不同页面会卸载旧 observer、创建新 observer；它不是 Shell remount 根因，也没有证据表明旧业务数据跨页面展示。它的全局作用域仍然过宽，可能让同一 observer 的不同业务 key 保留不应复用的数据，因此本批移除全局配置。

真实根因是 **lazy route chunk 首次加载 + 每个页面自己的 query pending/loading 内容替换**，而不是 App Shell、Outlet、Sidebar、Topbar 的 remount，也不是 CSS transition、opacity 或人为延迟。

## 修复内容

### 1. 保留代码拆分，增加目标路由预取

新增 `frontend/src/lib/route-preload.ts`，复用 Calendar/Goals/Team 的 lazy loader。`NavItem` 在 `pointerenter` 和 `focus` 时调用 `onPrefetchRoute`，因此用户点击侧边栏前目标 chunk 已开始加载；没有一次性加载全部业务页面，也没有取消代码拆分。

### 2. 收紧 React Query placeholder 作用域

- 删除 `frontend/src/main.tsx` 的全局 `placeholderData(previousData)`。
- 仅在数据统计页同一页面的指标/时间范围 query 上保留 previous data，满足同页筛选切换的稳定性需要。
- 跨业务路由不再可能由全局配置借用上一业务 observer 的 placeholder 数据。

### 3. 保持页面稳定结构

本批没有把所有页面泛化改成全屏 loading，也没有改动已经通过人工验收的页面内部 Tab 结构。现有主要业务页面保持 `PageContainer → PageHeader → PageBody`；路由 pending 时由该页面自己的局部 skeleton/loading 占位，PageContainer 和 PageHeader 不消失。

### 4. 真实 E2E 回归增强

Playwright 现在覆盖：

- 冷启动首次进入主要业务路由；
- 第二轮及后续热缓存进入；
- 连续 5 轮侧边栏快速导航；
- lazy chunk 在 hover/focus 预取后再点击；
- 12 个连续 `requestAnimationFrame` 几何采样；
- Shell/Sidebar/Topbar/PageContainer DOM identity；
- PageHeader、PageContainer child count、最小高度、宽度和 document overflow；
- API gate 阻塞下的路由稳定性；
- console error、pageerror；
- Chromium、mobile-chromium 及 production preview。

E2E 中使用人工 API gate 仅用于验证慢请求条件，不是产品延迟或视觉掩盖方案。

## 修复前后生命周期差异

```text
修复前：
点击侧边栏
  → lazy chunk 尚未完成 / 新页面 query pending
  → Suspense 或页面 LoadingState
  → 真实页面内容

修复后：
pointerenter/focus
  → 目标 lazy chunk 预取
点击侧边栏
  → Persistent App Shell / Sidebar / Topbar / Main Frame 保持原节点
  → 当前页面自己的稳定 skeleton 或已缓存内容
  → 当前页面真实数据
```

没有添加 `setTimeout`、人为 delay、全页 spinner、opacity/fade、固定超大高度或异常吞除。
