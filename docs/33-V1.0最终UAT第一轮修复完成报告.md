## 3. 根因与最终设计

### 页面横向位移

根因是页面内容高度改变时浏览器纵向滚动条出现/消失，导致可用 viewport 宽度变化；部分页面容器未显式保持统一全宽。最终在根级使用 `scrollbar-gutter: stable`，并统一 `PageContainer` 的 `w-full` 约束。没有针对单个页面设置偏移补丁。

### 目标量化指标校验

根因是可选数字输入的空值进入表单后形成 `NaN`，并被数值校验当作错误；同时校验没有完整绑定“是否选择指标”。现在空值归一化为未设置，并只在存在指标时要求目标值。

### 时区数据流

账号的 `account.timezone` 是唯一配置源：设置页只能从支持的 IANA 列表选择；日历把账号时区墙上时间转换为 UTC 后提交；请求继续携带兼容字段，但服务端保存前强制覆盖为当前账号时区；展示再按账号时区格式化。工作量、营业额、复盘、统计和团队快照继续读取同一账号时区。

### 日历拖拽创建

周/日视图启用 FullCalendar `selectable`、`selectMirror` 和移动端长按延迟。选段回调仅在 `timeGridWeek`/`timeGridDay` 打开新建日程，并把所选起止 instant 转成账号时区的 `datetime-local` 值。

### 常用联系人

新增 `calendar_contacts`：`id`、`user_id`、可选 `name`、`email`、创建/更新时间。`user_id` 外键级联删除；`(user_id, lower(email))` 唯一；所有读写条件都包含当前普通用户 ID。API 为：

- `GET/POST /api/calendar/contacts`
- `PUT/DELETE /api/calendar/contacts/{contact_id}`

管理员经过现有 `requireUser` 边界被拒绝，联系人不会关联为系统账号或团队成员。

### PV 与净营业额

集中使用 `frontend/src/lib/pv.ts`，固定 `1 PV = ¥12.5`。覆盖“今日工作量”和“营业额”两个同时出现 PV/净营业额的普通录入表单；输入 PV 更新金额，输入金额更新 PV，清空 source 同时清空 paired field。后端一致性校验、财务规则和导入规则未改。

### 团队图滚动跳动

原实现监听选中节点并调用 `scrollIntoView`，会滚动最近可滚动祖先，切换 Tab 或搜索定位时可能带动页面。现已删除该逻辑，画布移动由 React Flow viewport 管理；关闭 Dialog 时使用 `focus({ preventScroll: true })` 恢复焦点。

### 导入 Wizard

前端以 `step: 1 | 2 | 3 | 4 | 5`、`type`、`file`、`job` 组成状态机。选择类型自动进入 Step 2；下载模板不是前置条件；上传成功进入预览；无阻塞错误才可进入 Step 5；只有 Step 5 的“确认导入”调用既有 `commitImport`。后端导入校验、幂等键和提交规则未改。

### 单字符搜索

Overlay 防抖门槛从 2 改为 1，完整页原本允许非空输入。OpenAPI 已是 `minLength: 1`，后端 service 原本只拒绝 trim 后空字符串，SQL 的 `ILIKE` 路径本身支持单字符，因此后端无需行为修改；集成测试补齐一致性和账号隔离证据。
