## 1. UAT2-01 团队搜索位置与 Tab 布局稳定

当前“搜索成员”被放在 Tabs 上方/右侧独立区域。关系图存在搜索功能，而历史快照不需要搜索，导致不同 Tab 高度不同，切换时主区域出现上下位移。

### 正确设计

关系图：

```text
团队关系图                                  [搜索成员________]
搜索可定位成员；使用画布控制调整视图，点击成员打开详情。
```

搜索框与“团队关系图”标题位于同一 Panel Header 行。

成员列表如需要搜索，同样放到“成员列表”Panel Header 右侧。

历史快照不渲染搜索框，也不为搜索框保留空白占位。

### 验收
- [ ] 关系图搜索位于 Panel Header 右侧。
- [ ] 成员列表搜索位于自身 Panel Header。
- [ ] 历史快照没有搜索控件。
- [ ] 三个 Tab 切换时 Tabs 与主要 Panel 顶边位置保持稳定。
- [ ] 不使用固定 margin/transform 做视觉补丁。

## 2. UAT2-02 数据统计“财年/自定义”高度一致

当前选择“财年”时只显示区间摘要；选择“自定义”时额外出现两个日期输入，导致时间范围工具条高度变化。

### 正确设计

时间范围栏统一高度、统一栅格：

```text
[本周] [本月] [自然年] [财年] [自定义]    [条件区]    2026-09-01 至 2026-09-30
```

- 非自定义：条件区保持同一布局高度，可为空，但容器高度不变。
- 自定义：条件区展示开始日期/结束日期。
- 财年：如需年度选择器，同高度展示。
- 不允许切换后整个统计内容上下跳动。

### 年度范围规则
1. 自然年：1 月 1 日至 12 月 31 日。
2. 财年：按当前系统既有财年规则计算。
3. 自定义：自由选择起止日期。

### 验收
- [ ] 本周/本月/自然年/财年/自定义切换时工具条外框高度一致。
- [ ] 主统计结果区域顶边位置不跳动。
- [ ] 自定义日期输入对齐。
- [ ] 财年区间计算正确。

## 4. UAT2-04 创建/录入型日期默认当天

不要机械把所有日期筛选器都改成当天。

### 应默认今天
- 新建目标：开始日期默认今天，截止日期默认今天；
- 新建营业额：业务日期默认今天；
- 财务流水：发生日期默认今天；
- 团队成员：加入日期默认今天；
- 其他明确属于“创建一条今天发生的业务事实”的日期字段。

### 不应机械默认今天
- 数据统计自定义区间；
- 历史查询；
- 报表筛选；
- 编辑已有历史记录；
- 已有业务语义明确要求其他范围的字段。

“今天”按当前账号业务时区计算，不按服务器 UTC 日期。

请扫描所有 date input/date picker，区分：
- 创建型日期；
- 筛选型日期；
- 历史编辑日期。

只对创建型统一默认值。

## 5. UAT2-05 时区选择器简化

数据库继续保存标准 IANA 时区，但 UI 不应直接把数百个 `Africa/*` 字母序列表作为第一视觉层级。

### 第一层：当前设备时区

```ts
Intl.DateTimeFormat().resolvedOptions().timeZone
```

展示类似：

```text
当前设备时区
日本（东京，UTC+9）
Asia/Tokyo

[使用当前设备时区]
```

### 第二层：常用地区

优先展示：
- 中国大陆（上海）— `Asia/Shanghai`
- 中国香港 — `Asia/Hong_Kong`
- 中国台湾（台北）— `Asia/Taipei`
- 日本（东京）— `Asia/Tokyo`
- 新加坡 — `Asia/Singapore`
- 英国（伦敦）
- 美国东部（纽约）
- 美国中部
- 美国山地
- 美国西部（洛杉矶）

UTC offset 必须根据当前日期和 DST 动态计算。

### 第三层：更多时区

可搜索：
- 中文地区名；
- 英文城市；
- IANA ID；
- UTC offset。

示例：

```text
上海
Tokyo
New York
UTC+8
Asia/Shanghai
```

### 验收
- [ ] 一眼可看到当前设备时区。
- [ ] 常用时区直观可理解。
- [ ] 更多时区仍保持完整 IANA 能力。

## 9. UAT2-09 PV/净营业额舍入与一致性

固定规则：

```text
1 PV = ¥12.5 净营业额
```

已确认：
- PV 保留 2 位小数；
- 净营业额保留 2 位小数；
- 十进制四舍五入；
- 禁止使用二进制浮点直接做精确相等判断。

示例：

```text
净营业额 = ¥11.00
PV = round(11 / 12.5, 2) = 0.88
```

必须允许保存，不能再提示“PV 与净营业额不一致”。

### 推荐统一算法

金额作为 source：

```text
pv = round(net_turnover / 12.5, 2)
```

后端校验：

```text
round(net_turnover / 12.5, 2) == submitted_pv
```

PV 作为 source：

```text
net_turnover = round(pv * 12.5, 2)
```

前端最后编辑字段仍为 source。

### 全局排查
- 今日工作；
- 营业额；
- 导入；
- 后端一致性校验；
- analytics/展示层；
- 共享 PV helper。

### 回归
- `100 PV ↔ ¥1250.00`
- `0.88 PV ↔ ¥11.00`
- `¥10.01 → 0.80 PV`
- `0 PV ↔ ¥0.00`
- 高值
- 空值

对于 `¥10.01 → 0.80 PV`，校验以“金额→PV 四舍五入后与提交 PV 一致”为准，不要求反算金额精确回到 10.01。
