# JL团队生意成长管理系统——UI 重构剩余页面与全局收尾设计 V1.0

## 1. 目标

在 Phase A、Phase B 已完成基础上，一次完成剩余前端 UI/UX 重构与全局视觉收尾。

本阶段包含：

1. 财务
2. 学习中心
3. 收入模拟
4. 复盘
5. 数据统计
6. 导入 / 导出
7. 设置
8. 全局搜索
9. 全局响应式一致性
10. 空状态、表格、按钮、Drawer/Sheet、Tabs 等视觉统一

本阶段仍然是纯前端重构，不得修改数据库结构、migration、后端 API 语义、OpenAPI 业务合约、权限模型、收入模拟公式、导入幂等规则、财务计算逻辑或统计口径。

## 2. 实施顺序

内部拆为以下子阶段，每个阶段独立 commit：

- C1：财务
- C2：学习中心
- C3：收入模拟
- C4：复盘
- C5：数据统计
- D1：导入/导出 + 设置
- D2：全局搜索
- D3：全局响应式与视觉一致性收尾

产品负责人不要求中途人工验收，全部完成后统一截图和验收。

## 3. C1 财务

当前财务页面把记录流水、自定义分类、月度预算、储蓄与应急资金、最近流水同时铺开，首屏负担过重。

新结构：

```text
财务                                      + 新增流水

[总览] [流水] [预算] [资金快照]
```

总览展示本月收入、本月支出、本月净现金流、预算使用情况、现金流趋势、支出分类分布和最近流水，避免大面积录入表单。

流水页以列表为主，提供搜索、日期筛选、类型筛选、分类筛选和 `+ 新增流水`。新增流水使用 Drawer/Sheet。分类管理作为次级操作，不长期占据半个页面。

预算页展示当前月份、总预算、已使用、剩余、预算进度和历史预算。新增/编辑预算使用 Drawer。

资金快照页展示储蓄、应急资金、快照日期和历史快照。新增快照使用 Drawer。

## 4. C2 学习中心

新结构：

```text
学习中心                                  + 新增学习

本周学习 185 分钟   进行中 3   已完成 2

[学习项目] [附件库]
```

学习项目页提供搜索、类型筛选、状态筛选、标签筛选。项目使用紧凑卡片或列表显示标题、类型、状态、进度、学习分钟、标签和最近更新。点击项目进入详情 Drawer，新增/编辑项目使用 Drawer。

附件库集中显示 PDF、TXT、Markdown、图片，支持文件名、类型、上传时间、关联项目、预览、解除关联和删除。避免巨大空状态框。

## 5. C3 收入模拟

收入模拟改为“计算工作台”，而不是传统超长表单。

```text
收入模拟                    [方案 ▼] [保存方案]

[模拟器] [保存方案] [方案比较]
```

模拟器分三块：

1. 基础数据：个人 PV、顾客 PV
2. 市场结构：12 个市场输入，桌面 3～4 列，手机 1～2 列
3. 奖励条件：年度成长状态、达标月数、BFI、BBI、双年奖金模式和其他已有条件

底部主操作为 `计算收入`。

桌面端右侧使用 sticky 结果面板，持续显示预计月度收入、主要奖金、一次性/年度奖励和合计预计收入；手机端结果区放在输入后方。

保存方案独立 Tab，显示方案名称、关键输入摘要、月度收入、一次性奖励、修改时间以及打开/复制/删除操作。

方案比较支持至少两个方案并排比较关键输入、市场结构、各奖金、月度收入、一次性奖励和合计。

不得修改任何计算公式。

## 6. C4 复盘

```text
复盘

[每日] [每周] [每月]
```

当前周期顶部先展示紧凑经营摘要：行动总数、PV、学习分钟、目标完成和适用周期的现金流。

随后填写做得好的、遇到的问题、下一步改进、下一周期聚焦和现有周期摘要字段。

把数据摘要和复盘文本放在一个连续工作区，不再切成两张巨大卡。底部或侧边提供最近历史复盘入口。

## 7. C5 数据统计

数据统计成为统一分析中心：

```text
数据统计

[工作量] [营业额] [目标] [团队] [财务]

本周 | 本月 | 本年 | 自定义
```

每个领域统一结构：顶部 3～5 个 KPI、一个主趋势图、一个分布/结构区、底部明细表。

单次只展示一个领域，不在同一页面堆所有图表。只使用现有 analytics API。

## 8. D1 导入 / 导出

现有业务逻辑保留。

导入采用步骤式布局：

```text
1 选择类型
2 下载模板
3 上传文件
4 校验预览
5 确认导入
```

当前步骤高亮，校验错误和警告视觉区分。

导出使用紧凑结构化列表，不给每一项独立大 Card：

```text
工作量      CSV  XLSX
营业额      CSV  XLSX
财务        CSV  XLSX
团队        CSV  XLSX
知识        JSON Markdown
完整账户    ZIP
```

## 9. D1 设置

设置页改为标准布局：

```text
设置

[账号] [偏好] [数据与安全]
```

账号：修改密码、当前账号信息。

偏好：用户时区。

数据与安全：完整数据导出、永久删除账户。危险操作区域单独放在底部，避免与普通设置混在一起。

## 10. D2 全局搜索

顶部搜索入口已经由 Phase A 提供。本阶段优化完整搜索体验。

点击顶部搜索后打开 Command/Search Overlay：输入关键词、显示按模块分组的前几条结果、支持键盘选择和 Enter 打开，并可“查看全部结果”进入完整搜索页。

完整搜索结果页保留搜索框、类型筛选和分组结果。搜索范围保持现有业务，不扩大为未支持的文档正文全文搜索。

## 11. D3 全局视觉收尾

统一 PageHeader、Tabs、Drawer/Sheet、空状态、表格、搜索框、筛选条、按钮、Badge、输入框、日期选择器、提示文字和错误状态。

空状态统一为小图标、一句标题、一句说明和一个主操作，避免大面积空框。

表格在桌面保证列宽、表头、hover 和操作列清晰；手机可横向滚动或切换卡片列表。

按钮统一 Primary、Secondary、Ghost、Danger，同一页面尽量只有一个主按钮。

重点检查 1280px、1440px+、平板宽度和手机窄屏，不得出现页面级横向溢出、Drawer 超屏、按钮挤成两行、标签错位或 sticky 遮挡底部。

## 12. 管理员端

本轮不重构管理员业务结构，只统一顶栏、页面容器、按钮、表格和空状态视觉。管理员仍保持独立导航体系。

## 13. 测试要求

每个子阶段单独测试。最终必须执行：

```bash
make lint
make test
make build
make check
make test-e2e
git diff --check
```

新增/更新前端测试至少覆盖：财务 Tabs、新增流水 Drawer、学习 Tabs、学习项目 Drawer、收入模拟 Tabs、sticky 结果区域响应式、复盘 Tabs、数据统计 Tabs/时间范围、导入步骤、设置 Tabs、顶部搜索 overlay、手机端核心页面、管理员端基础布局。

## 14. 最终验收标准

全部完成后：

- 所有普通用户页面遵循统一信息架构；
- 不再存在“大表单长期占首屏”的主要页面；
- 侧栏层级清晰；
- 页面标题不重复；
- 首页、今日工作、目标、团队、日历、财务、学习、收入模拟、统计均形成明确任务中心；
- 桌面与手机均可用；
- 所有原 URL 继续有效；
- 无后端/数据库业务变化；
- 自动化测试全部通过。
