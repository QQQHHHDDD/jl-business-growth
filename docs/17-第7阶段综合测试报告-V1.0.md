# JL团队生意成长管理系统——第7阶段综合测试报告 V1.0

## 1. 测试基线

- 测试阶段：第 7 阶段综合测试。
- 测试对象：Phase 0～6、V1 收口 P0-01～P0-11 及本阶段发现的修复。
- 收口前基线：`86c87cb fix: close V1 release blockers`。
- 测试分支：`master`。

## 2. 测试环境

- Ubuntu 内网开发/验收主机。

- Go 1.27 项目工具链，Node.js 项目本地工具链，React/Vite 前端。
- 后端使用本地 `httptest` 和 PostgreSQL；文件使用临时目录；邮件使用 file outbox。

- 未配置真实 SMTP，未使用生产数据库、生产密钥、生产域名或云服务器。

- User B 不能读取 User A 的工作量或下载 User A 的文件；文件列表只返回当前账号对象。

## 12. 发现缺陷与修复

### P1-01：有数据时工作量分析接口返回 500

- 复现：向 `daily_worklogs` 写入一条记录后请求 `/api/analytics/worklogs`。
- 原因：分析查询错误地从 `daily_worklogs` 读取不存在的 `reading_minutes`、`audio_minutes` 列；空数据时该问题未触发。
- 修复：`backend/internal/analytics/service.go` 改为从 `learning_sessions` 查询每日学习分钟，并显式转换整型结果。
- 回归：Phase 7 安全专项中的有数据分析请求、50 用户性能用例均通过。
- 状态：已修复，P1 清零。

### P1-02：并发登录造成 Argon2 资源峰值和 500

- 复现：50 个模拟用户同时登录，原实现会同时启动过多 Argon2 派生，观测到 50 个 500，进程堆峰值约 3.3 GiB。
- 修复：`backend/internal/auth/password.go` 对 Argon2 派生增加容量为 4 的进程内并发闸门，Argon2 参数和密码验证语义不变。
- 回归：`backend/internal/auth/password_test.go` 并发校验测试、50 用户性能用例通过；峰值 RSS 降至约 543 MiB，0 个 5xx。
- 状态：已修复，P1 清零。

### 测试隔离缺陷：Phase 7 清理后系统财务分类丢失

- 复现：`TRUNCATE accounts CASCADE` 会连带清空 `finance_categories`，而新 Phase 7 harness 未恢复 `user_id IS NULL` 的系统分类，导致后续 E2E 财务页面没有选项。
- 修复：Phase 7 harness 清理后恢复 5 个系统分类，并与现有 Phase 5/6 集成测试保持一致。
- 状态：已修复，属于测试辅助缺陷，不是生产业务缺陷。

未发现未修复的 P0/P1。没有因失败删除断言、降低测试标准或跳过失败测试。

## 13. 剩余技术债务

- 真实 SMTP、真实开发进程重启、实际网络中断和 PostgreSQL 暂停仍需在隔离的发布演练环境验证；本次未改用真实外部服务。
- 性能测试未安装或启用 `pg_stat_statements`，SQL 慢查询和锁等待的生产基线仍需建立。
- Argon2 并发上限当前是代码常量 4；上线前应结合生产 CPU/内存、反向代理并发和登录峰值做容量确认，但不得通过降低密码哈希参数解决。
- P95 包含登录验证和混合请求，不能替代真实用户 UAT 对手机高频录入速度的判断；RSS 会受 Go allocator 和主机负载影响，本次末次采样约 593 MiB。

以上项目不阻塞进入人工 UAT；真实生产发布前必须完成其中的环境级验证。
