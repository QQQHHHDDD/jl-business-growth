# 1. 总体要求

本轮不是重新设计整个系统，而是对 Final UAT 中实际暴露的问题进行集中收口。

实现原则：

1. 以真实用户操作体验为准，不通过修改文案掩盖交互或数据问题。
2. 不修改已确认的收入模拟公式、财务规则、工作量业务定义和权限模型。
3. 所有新交互必须兼顾 Desktop 和 Mobile。
4. 所有涉及用户时区的业务，统一以账号级 IANA 时区为唯一用户配置来源。
5. 如某问题的根因是公共 UI 组件或 App Shell，应做全局修复，不得只针对单页打补丁。
6. 修改完成后必须新增对应回归测试。
7. 不删除已有失败断言来“让测试通过”。
8. 若常用联系人功能确实需要持久化数据结构，允许在说明理由后新增**最小必要 migration**；除此之外不要主动扩展数据库结构。

# 2. 问题清单与正式需求

## UAT-01 品牌名称在侧边栏溢出

### 现象

展开侧边栏时：

```text
JL团队生意成长管理系统
```

在品牌区域出现宽度不足/溢出问题。

### 要求

- 正式名称继续使用：`JL团队生意成长管理系统`。
- 展开侧边栏时必须完整可读，不允许横向溢出。
- 优先通过品牌区域布局、换行、宽度和字号处理解决，不要仅为了品牌文字盲目加宽整个侧边栏。
- 收起状态继续只显示品牌图标/`JL`。
- 品牌区域高度变化不得造成导航项跳动。

### 验收

在 1440、1280、1024 宽度下均完整、稳定、无溢出。

## UAT-02 页面/Tab 切换时主内容发生轻微横向位移

### 现象

在“梦想与目标”等模块切换：

- 目标地图
- 目标列表

时，侧边栏没有变化，但主内容整体会轻微向左/右移动。其他页面也存在类似现象。

### 要求

做全局排查，不只修梦想与目标。

重点检查：

- 页面滚动条出现/消失导致的 viewport 宽度变化；
- `100vw` 与 scrollbar 的组合；
- 页面容器 max-width / padding 是否在不同 Tab 使用不同规则；
- Dialog/Sheet 打开关闭后的 body scroll lock；
- Tabs 空状态和有数据状态；
- 页面高度变化导致 scrollbar gutter 改变。

允许使用类似：

```css
scrollbar-gutter: stable;
```

等方案，但必须先确认真实根因。

### 验收

以下切换过程中，主内容左边界和中心轴不得产生肉眼可见横向跳动：

- 目标地图 ↔ 目标列表 ↔ 梦想板
- 团队关系图 ↔ 成员列表 ↔ 历史快照
- 财务各 Tab
- 学习中心各 Tab
- 收入模拟各 Tab
- 复盘各 Tab
- 数据统计各领域
- 设置各 Tab
- 导入步骤切换

建议增加可自动验证的 layout regression，至少比较核心容器 bounding box。

## UAT-03 新建目标的量化指标错误地成为必填

### 现象

新建目标时只填写“目标名称”，点击创建后，焦点跳到“目标值”，但产品定义中量化指标是可选项。

### 正确规则

- 未选择量化指标时：
  - 目标值不必填写；
  - 允许正常创建目标。
- 只有当用户选择了量化指标时：
  - 才校验目标值；
  - 单位按现有业务规则处理。
- 不得通过自动聚焦“目标值”误导用户以为量化指标必填。

### 验收

仅填写目标名称即可成功创建一个非量化目标。

## UAT-04 梦想图片选择后自动上传

### 当前问题

用户选择图片后还需要再次点击“上传”，存在多余操作。

### 要求

选择文件后：

1. 自动开始上传；

3. 成功后立即显示预览；
4. 不再要求再次点击“上传”；
5. 失败时显示明确错误并提供重试；
6. 保持现有文件归属、权限和清理规则。

如果新梦想尚未保存，需要避免取消创建后留下不可控孤儿文件；复用现有文件清理机制或设计最小的临时关联处理。

## UAT-06 所有时区修改必须使用选择器，禁止自由输入

### 产品规则

用户只有一个全局业务时区。

时区只在：

```text
设置 → 偏好
```

中修改。

### 要求

1. 设置页的 IANA 时区字段改成可搜索选择器/Combobox。
2. 用户只能选择合法 IANA timezone，不允许保存任意字符串。
3. 其他业务页面：
   - 不提供时区编辑输入框；
   - 如需展示，仅显示当前账号时区。
4. 日历、工作量、营业额、复盘、统计、团队快照等均读取同一账号时区。
5. 如果日历后端仍保留 event timezone 字段，为兼容现有数据结构：
   - 新建/编辑时由前端或服务端自动使用账号时区；
   - 普通用户界面不再暴露独立事件时区输入。

### 验收

全系统普通用户界面中，不再出现手工输入 `Asia/Shanghai` 这类时区字符串的表单。

## UAT-09 日历增加“常用联系人”

### 产品目标

邀请日程时，不需要每次手工重复输入邮箱。

### 正式需求

新增**当前账号私有**的常用联系人能力。

最小数据：

- 联系人姓名（可选但建议填写）；
- 邮箱（必填）；
- 同一账号内邮箱去重。

日程邀请人输入改为：

- 可搜索并选择已保存联系人；
- 允许直接输入新的合法邮箱；
- 当输入一个未保存的新邮箱并加入邀请后，弹出或提供明确选项：

```text
是否保存为常用联系人？
```

选择“保存”后写入当前账号常用联系人。

### 隔离规则

- 常用联系人只属于当前普通用户；
- 多账号之间不共享；
- 管理员不能读取普通用户联系人内容；
- 不把联系人自动当作系统账号或团队成员。

### 数据库边界

如果当前系统没有可复用的安全持久化结构，本项允许新增最小表/migration。

建议先检查现有模型，再决定。

如新增，建议类似：

```text
calendar_contacts
- id
- user_id
- name
- email
- created_at
- updated_at
```

具体命名按项目规范。

必须补：

- ownership；
- email validation；
- per-user unique；
- delete/update；
- API integration tests。

不要为了避免 migration 把正式联系人长期数据偷偷塞进 `localStorage`。

## UAT-12 PV 与净营业额全系统双向实时同步

### 业务规则

固定：

```text
1 PV = ¥12.5 净营业额
```

### 要求

任何普通业务表单中，只要同时出现：

- PV
- 净营业额

这两个字段，就必须双向实时同步。

例如：

### 今日工作

用户输入：

```text
PV = 100
```

立即得到：

```text
净营业额 = ¥1250.00
```

用户改为：

```text
净营业额 = ¥2500.00
```

立即得到：

```text
PV = 200
```

### 营业额模块

同样执行。

### 实现规则

- “最后被用户编辑的字段”作为当前 source；
- 自动计算另一个字段；
- 不产生输入循环；
- 金额保留 2 位小数；
- 保持后端现有一致性验证；
- 编辑历史记录时同样生效。

### 全局排查范围

至少检查：

- 今日工作；
- 营业额；
- 其他任何同时出现 PV + 净营业额的普通录入表单。

模板导入/导出不需要在客户端偷偷改用户文件中的原始数据，仍按现有导入校验规则处理。

### 文案

既然已经实时同步，删除/改写无实际价值的：

> 按 PV 换算净营业额……

类提示。

可以保留一条简洁规则：

```text
1 PV = ¥12.5
```

## UAT-13 团队关系图交互重构

### 初始状态

进入“团队 → 关系图”时：

- 图自动 Fit View；
- 整体居中；
- 不贴左上角；
- 用户可自由拖动画布；
- 支持滚轮/控制按钮缩放。

### 节点视觉

每个节点默认只展示：

```text
成员姓名
```

不要在节点中堆：

- level；
- city；
- code；
- status；
- 其他详细字段。

状态可通过极轻量视觉样式表示，但不要增加文字噪声。

### 点击节点

点击节点后：

- 在页面中央打开 Modal/Dialog；
- 默认是成员详情查看态；
- 展示现有成员信息；
- 提供“编辑”按钮；
- 点击编辑后允许修改现有可编辑字段；
- 保存后图和列表同步刷新。

不要默认点击就直接编辑。

### 切回关系图的滚动问题

当前从成员列表/其他 Tab 切回关系图时可能自动向下滚动。

必须排查：

- autofocus；
- `scrollIntoView`；
- React Flow fitView；
- focus restoration；
- Tab mount effect；

等根因。

### 验收

切回关系图时页面滚动位置稳定，不发生非用户主动触发的向下跳动。

## UAT-15 导入/导出左侧导入流程改成真正的分步 Wizard

### 当前问题

顶部显示：

1. 选择类型
2. 下载模板
3. 上传文件
4. 校验预览
5. 确认导入

但页面下方同时展示多个后续阶段内容，步骤与实际页面状态不一致。

### 正确交互

导入区域一次只展示当前步骤需要完成的内容。

### Step 1：选择类型

只显示：

- 每日工作量
- 营业额历史
- 财务流水
- 团队成员

选择后进入下一步。

### Step 2：下载模板

只显示：

- 当前类型；
- 下载对应模板；
- “下一步”；
- “上一步”。

不强制用户必须点击下载才能继续，因为用户可能已有模板。

### Step 3：上传文件

只显示：

- 当前类型；
- 文件选择；
- 上传并校验；
- 上一步。

上传成功后进入 Step 4。

### Step 4：校验预览

只显示：

- 校验结果；
- 警告；
- 错误；
- 将新增/更新/跳过的摘要；
- 数据预览。

没有阻塞错误时允许进入 Step 5。

### Step 5：确认导入

显示最终摘要和明确的：

```text
确认导入
```

此时才正式写入业务数据。

### Stepper 行为

- 当前步骤明显高亮；
- 已完成步骤有完成态；
- 未到达步骤不可假装“已经进行”；
- 允许返回已经完成的前一步；
- 返回时不要丢失无必要丢失的选择状态。

### 导出

右侧“结构化导出”不是导入步骤，可继续作为独立区域存在，但视觉上明确与左侧 Wizard 分开。

## UAT-16 全局搜索最小关键词长度从 2 改为 1

### 当前问题

搜索 Overlay 提示：

```text
输入至少 2 个字符
```

### 新规则

输入 **1 个字符** 就可以搜索。

例如：

```text

```

即可返回匹配结果。

### 要求

同时检查：

- 前端输入长度判断；
- debounce；
- Search Overlay；
- `/app/search`；
- OpenAPI validation；
- 后端 service/query validation；

避免只改 placeholder，但请求仍被后端拒绝。

空字符串仍然不执行搜索。

### 验收

- 单个中文字符可搜索；
- 单个英文字母也按相同规则工作；
- 220ms 防抖可保留；
- 搜索权限和账号隔离不改变。
