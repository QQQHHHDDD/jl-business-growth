# JL团队生意成长管理系统——V1.0 前端视觉升级 UI-B1 最终精修 Prompt V1.0

## 0. 任务定位

当前 `/app/analytics` 数据统计页整体视觉方向已经通过。

本轮只做一次 **UI-B1 最终视觉精修**，目标是继续降低“传统后台 / 管理系统”感，同时保持当前已经成立的青春、活力、成长感视觉语言。

本轮完成后，如人工视觉确认通过，即冻结 UI-B1 视觉语言，并进入 UI-B2：首页 + 梦想与目标。

本轮不得扩大范围，不得修改业务逻辑、数据结构、查询规则、API、路由、权限或其他业务页面。

---

## 1. 一级业务 Tabs 精修

当前：

```text
工作量 / 营业额 / 目标 / 团队 / 财务
```

仍略带传统后台 Tab bar 感。

调整目标：

- 改成更完整、更现代的 rounded segmented rail；
- 外层使用非常浅的中性/青绿色轨道背景；
- 整体圆角约 14–16px；
- active 项使用白色 surface；
- active 项增加非常轻的 shadow；
- active 文字使用 brand color；
- inactive 项保持中性深色；
- hover 只做轻微 surface 变化；
- 保持现有 Radix Tabs 语义、键盘行为、横向滚动与业务切换逻辑。

禁止：

- 不改 Tab 数量；
- 不改顺序；
- 不改业务切换；
- 不使用高饱和背景；
- 不做夸张滑块动画。

---

## 2. 时间范围区域精修

当前：

```text
本周 / 本月 / 自然年 / 财年 / 自定义
```

视觉上仍略像传统筛选工具栏。

调整目标：

- 时间范围本身使用更紧凑的 pill / segmented control；
- active 项允许使用品牌青绿实底 + 白字；
- inactive 项使用柔和浅色 surface；
- 右侧日期范围弱化为 metadata；
- 整个区域减少“大白框工具条”感；
- 保留现有稳定高度，不制造布局跳动；
- 自定义日期出现时，输入框与 segmented control 在视觉上连贯；
- input 使用 UI-A 已确认的圆角、surface、focus ring；
- 保持日期范围、自然年、财年、自定义日期等所有业务规则不变。

---

## 3. KPI MetricCard 精修

现有五张 KPI 卡方向已经通过，不再更换色彩体系。

仅做以下微调：

- 圆角统一到约 18–20px；
- 进一步弱化硬边框；
- 使用柔和 shadow 建立层次；
- KPI value 字号和视觉权重略提升；
- label 与 value 之间的垂直节奏更舒展；
- icon 容器更圆润；
- 当前五种 tone 保持：
  - 开启对话：mint / teal
  - 深入对话：blue
  - 分享故事：coral
  - 筛选：yellow / orange
  - 会面：purple
- 可以保留极轻 abstract blob / gradient decoration；
- decoration 对比度降低，不能抢数字。

不允许：

- 增加假环比；
- 增加假趋势；
- 增加 sparkline；
- 再引入更多颜色；
- 改 KPI 数据来源。

---

## 4. “工作量趋势”与“结构摘要”卡片精修

这两个区域仍带有较明显的传统后台卡片感。

### 工作量趋势

- major card 统一使用 18–20px 圆角；
- border 降低对比；
- 使用轻 soft shadow；
- 弱化 header 横向 divider；
- 更多使用 spacing 建立标题与内容层次；
- 指标 chip 保持低强度；
- 不改趋势图实现、数据、切换逻辑。

### 结构摘要

保留：

```text
Buffer
提供机会
顾客跟进
阅读分钟
音频分钟
```

视觉调整：

- 减少表格列表感；
- row divider 进一步弱化；
- icon 色块更柔和；
- label/value 层级更明确；
- value 使用 tabular nums；
- 每行 vertical spacing 更舒展；
- 保留当前左右结构和数据来源。

---

## 5. 统计明细 DataTable 精修

当前底部统计表仍是整页最传统的后台视觉之一。

调整目标：

- 表格外层使用 16–18px 圆角容器；
- 弱化网格线与 cell 边框；
- 表头使用非常淡的 tinted background；
- 表头文字权重略提高；
- 行高适度增加；
- row hover 非常轻；
- 第一列“周期”稍加强调；
- 数值类列使用 tabular nums；
- 表格与上方卡片风格统一；
- 移动端保持现有横向滚动与 min-width，不改变响应式逻辑。

禁止：

- 不改变列；
- 不改变排序；
- 不改变数据；
- 不改变表格业务逻辑；
- 不移除现有可访问语义。

---

## 6. 大型 Empty State 精修

团队、财务及类似大面积无数据状态目前仍偏“默认后台空状态”。

调整目标：

- 弱化硬边框；
- 使用轻 tinted surface；
- 插画略放大；
- 统一成长主题原创 SVG 语言；
- 保持标题 + 解释 + 可选真实 CTA；
- 有真实业务入口才显示 CTA；
- 不同空状态可使用不同主题图形，但保持同一视觉语言。

建议主题：

- 团队：多人 / 节点 / 成长线；
- 财务：钱包 / 简化趋势 / 小叶片；
- 趋势：成长曲线 / 太阳 / 叶片。

禁止加入不存在的业务入口。

---

## 7. “暂无趋势”状态精修

当前文案与交互已通过，保留：

```text
暂无趋势

再记录几个周期后，这里会逐渐形成你的成长轨迹。

[去记录工作量]
```

仅调整：

- 插画略微放大；
- CTA 使用更完整的品牌主按钮视觉；
- 卡片内部上下留白更自然；
- 不改变 CTA 路由；
- 不改变业务判断。

---

## 8. Hero 中的太阳图形必须修正

当前 Hero 整体方向已经通过，**不再修改 Hero 布局、成长曲线、叶片、文案或整体色彩体系**。

但当前太阳识别度不足，视觉上更像：

```text
风车 / 齿轮 / 几何装饰符号
```

而不是用户第一眼就能认出的太阳。

本轮必须只精修太阳本体。

目标：

> 一眼明确识别为“太阳”，同时保持年轻、轻插画、清爽、不幼稚。

太阳造型要求：

1. 使用更清晰的圆形太阳主体；
2. 中心圆要有足够面积，避免只是细线交叉中心；
3. 光芒从圆心自然向外发散；
4. 建议 8–12 根光芒；
5. 光芒允许轻微长短变化，避免机械式完全等长；
6. 线条端点尽量圆润；
7. 可以使用暖黄色 / 柔和橙黄色；
8. 可使用非常轻微的中心渐变，但不要复杂；
9. 整体略带插画感，而不是 icon / logo / mechanical symbol；
10. 保持当前尺寸级别，不显著放大，不抢 Hero 标题视觉。

禁止：

- 不增加第二个太阳；
- 不增加云朵、人物、星星等新装饰；
- 不修改成长曲线；
- 不修改叶片；
- 不修改 Hero 高度；
- 不重新设计 Hero；
- 不让太阳变成儿童贴纸风格。

## 9. 页面整体层次

最终页面应建立清晰的三个视觉层：

```text
Canvas
↓
Normal Surface
↓
Hero / KPI / Important Surface
```

要求：

- 普通内容和重点内容不要全部处于同一个平面；
- 依靠背景、surface、shadow、spacing 建立层次；
- 不靠更多颜色堆叠；
- 不靠更粗边框；
- 不靠 glassmorphism。
