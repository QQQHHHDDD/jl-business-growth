## 1. UAT3-B2-01：日历 Hover 详情浮层层级错误

### 现象

在月视图中鼠标悬停事件后，事件详情浮层向下展开，但下方日期单元中的日期数字仍显示在浮层上方，出现“日期穿透浮层”的视觉问题。

### 根因排查

不要只改截图中的某个日期。系统检查：

- `.fc-daygrid-day`
- `.fc-daygrid-day-number`
- `.fc-daygrid-event`
- today 标记
- event hover card / tooltip / popover
- 父级元素的 `position` / `z-index`
- `transform`
- `filter`
- `opacity`
- `overflow`

确认是否存在局部 stacking context 导致浮层无法覆盖后续日期单元。

### 最终层级原则

```text
普通日期单元
< 日期数字
< 日历事件
< 当前 hover/focus 事件
< 事件详情浮层
< Dialog / Sheet / Modal
```

事件详情必须覆盖所有日期数字、today 标记和其他日历事件。

如当前 Hover 卡片使用日历网格内部 absolute 定位，优先考虑统一 Popover/Portal，使浮层脱离 FullCalendar 局部 stacking context。

### 边界要求

同时验证：

- 靠近页面底部时不会超出 viewport；
- 靠近右侧时能调整方向；
- 不被日历容器裁切；
- hover/focus 均可查看；
- 一天多个事件时不会互相覆盖异常；
- 长标题、受邀人信息可完整查看。

### 验收

至少覆盖月、周、日视图，当前日期和非当前日期，100% 与 125% 浏览器缩放。

## 2. UAT3-B2-02：周/日视图拖动创建导致白屏

### 严重级别

**P1**

### 现象

用户在：

```text
日历 → 周视图 / 日视图 → 鼠标拖动选择时间段
```

时页面直接白屏，需要刷新才能恢复。

禁止通过关闭拖动功能、吞异常或自动刷新规避。

### 第一要求：先得到真实异常

必须实际复现并记录：

1. 浏览器 Console 完整 error；
2. React component stack；
3. Network 是否发出异常请求；
4. FullCalendar `select` 回调参数；
5. 账号时区；
6. `timeGridWeek` / `timeGridDay`；
7. `allDay`；
8. `start` / `end` / `startStr` / `endStr`；
9. 是否产生 Invalid Date；
10. 白屏前最后一次 state 更新。

完成报告中必须写明真实异常文本和根因，不得只写“已修复”。

### 重点排查

检查：

- `select`
- `selectAllow`
- `selectMirror`
- `dateClick`
- `eventDrop`
- `eventResize`
- 新建日程 Dialog 初始化
- `datetime-local` 转换
- 用户时区 → UTC
- UTC → 用户墙上时间
- `end` 为 null/undefined 的情况
- `toISOString()` 对 Invalid Date 调用
- 不合法 timezone
- 条件渲染引用空对象
- ErrorBoundary 是否缺失

特别确认 FullCalendar 的 selection end 是否在某些路径为空或转换后非法。

### 正确交互

周/日视图：

1. 鼠标按下；
2. 拖出时间段；
3. 松开；
4. 打开“新建日程”中央 Dialog；
5. 开始时间 = 选择开始；
6. 截止时间 = 选择结束；
7. 自动使用账号全局时区；
8. 用户填写标题/联系人；
9. 保存；
10. 日程立即出现；
11. 页面不白屏、不跳转、不刷新。

### 防护

即使未来出现意外异常，也不应让整个 App Shell 变白。应有适当 Error Boundary，但 Error Boundary 不能替代根因修复。

### 自动化要求

新增真实浏览器 E2E：

#### 周视图

```text
进入周视图
拖动 09:00 → 10:30
确认 Dialog 打开
确认起止时间
填写标题
保存
确认事件出现
```

#### 日视图

同样执行一次。

额外覆盖：

- 向上拖动；
- 30 分钟；
- 90 分钟；
- 跨小时；
- 靠近 00:00；
- 靠近当天结束；
- 取消 Dialog；
- 保存失败回滚；
- Console 无 uncaught exception。

## 3. UAT3-B2-03：复盘与侧边栏路由切换仍闪动

### 现象 A：复盘

在：

```text
每日 → 每周 → 每月
```

切换时仍能明显看到闪一下。

### 现象 B：全局路由

点击不同侧边栏项目进入新页面时，也会闪。

第一批只解决了部分“首次加载闪动”，本轮必须继续定位“Tab 切换”和“路由切换”的真实根因。

### 必须实际使用浏览器分析

建议使用：

- Chrome Performance
- React Profiler
- Playwright trace/video
- 临时开发日志记录 mount/unmount

回答：

1. App Shell 是否被重新 mount？
2. Sidebar / Topbar 是否重建？
3. `<Outlet>` 是否因为 `key` 改变重建？
4. Query 是否出现 `data → undefined → loading → data`？
5. 复盘三类是否使用完全不同组件树？
6. Tabs 切换是否改变容器高度？
7. Skeleton 与最终页面高度是否不同？
8. scrollbar gutter 是否变化？
9. 是否存在 `key={location.pathname}` / `key={reviewType}`？
10. 是否存在页面进入后的二次 navigate/replace？

### 复盘专项

每日、每周、每月应共享同一个 workspace shell：

- PageHeader 保持；
- Tabs 保持；
- 外层 Panel 保持；
- 仅数据和必要字段变化；
- pending 时不显示 EmptyState；
- 最近周期列表不要先消失再出现；
- 加载态尺寸与最终内容一致。

如当前三种周期因为 key 或条件分支导致整棵树重新 mount，应改成稳定共享壳。

### 全局路由专项

以下结构必须持续存在：

```text
Sidebar
Topbar
PageContainer
```

路由变化只替换业务内容区。

禁止：

- 全 Shell 重新挂载；
- 内容区先完全清空；
- opacity 动画掩盖；
- `setTimeout`；
- 固定延迟。

可以根据现有实现合理使用：

- TanStack Query `placeholderData`；
- 保留上一份数据；
- 稳定 query key；
- 局部 Skeleton；
- 稳定 Outlet；
- 移除不必要 route key。

### 人工验收

复盘：

```text
每日 → 每周 → 每月 → 每日
```

连续 10 次。

侧边栏：

```text
首页
→ 今日工作
→ 日历
→ 团队
→ 财务
→ 学习中心
→ 复盘
→ 数据统计
→ 设置
→ 首页
```

重复 3 轮。

不得出现：

- 整块白屏；
- EmptyState 闪现；
- Sidebar/Topbar 闪动；
- 内容区宽度变化；
- 页面明显横向/纵向跳动。
