# JL团队生意成长管理系统——V1.0 前端视觉升级总 Prompt V1.0

## 0. 任务定位

当前系统功能、信息架构和主要页面布局已经基本稳定。

本轮目标不是重做产品结构，而是把现有“传统企业后台 / 正式管理系统”视觉，升级为更符合 JL 团队气质的：

> 年轻、活力、成长感、轻品牌化、清爽但更有表现力的现代产品界面。

核心原则：**功能基本不变、布局基本不变、视觉系统全面升级。**

参考产品负责人提供的“青春活力版数据统计页视觉稿”，将其作为本轮最高视觉参考之一。

---

## 1. 不需要重做的内容

除非为视觉一致性确有必要，否则不要改变：

- 现有信息架构
- 路由结构
- 左侧导航分组逻辑
- 页面主要布局
- 业务字段
- 表单字段
- 后端 API
- 数据库 schema
- 权限模型
- PV/营业额业务规则
- 日历、团队、财务等既有交互
- 已通过 UAT 的核心功能

本轮以“换视觉语言”为主，不以“重做产品”为主。

---

## 2. 目标视觉气质

关键词：

- 青春
- 活力
- 成长
- 希望感
- 轻盈
- 友好
- 现代
- 清爽
- 有品牌辨识度

不要做成：
- 经典 ERP
- 政务系统
- 银行后台
- 传统 BI 仪表盘
- 灰白企业管理系统

也不要做成：
- 儿童产品
- 过度糖果色
- 满屏渐变
- 游戏 UI
- 高饱和霓虹
- 复杂玻璃拟态
- 炫技型动效

目标是：

> “年轻团队每天愿意打开使用的成长管理系统”，而不是“严肃公司要求员工填报的后台”。

---

## 3. 视觉参考方向

### 3.1 整体背景

- 页面仍以浅色为主
- 使用柔和冷白 / 浅灰蓝背景
- 可加入极淡的青绿、蓝、紫、暖黄渐变光斑
- 不使用大面积纯灰背景
- 页面仍应保持较高信息可读性

推荐基础背景：
- `#F7FAFC`
- `#F8FBFF`

局部氛围色只作为装饰。

### 3.2 品牌主色

保留 JL 现有绿色品牌认知，但升级为更年轻的青绿体系。

建议：

```text
Primary 50   #ECFDF5
Primary 100  #D1FAE5
Primary 200  #A7F3D0
Primary 400  #34D399
Primary 500  #14B8A6
Primary 600  #0F8F83
Primary 700  #0F766E
```

主色用于：
- 主按钮
- 当前导航
- 主要 Tab
- 关键 CTA
- 品牌标识
- 成长类信息

---

## 4. 辅助色体系

允许比当前版本更“花”，但必须有规则。

建议辅助色：

```text
Blue      #60A5FA
Purple    #A78BFA
Coral     #FB7185
Orange    #FB923C
Yellow    #FACC15
Mint      #6EE7B7
Sky       #38BDF8
```

原则：
- 一个页面通常只使用 1 个主品牌色 + 2～3 个辅助色
- 彩色主要用于 KPI、图标背景、Badge、图表、空状态、局部插画
- 不要让正文、表格和表单大面积彩色化

---

## 5. 统一 Design Tokens

先建立或整理统一 Design Tokens，不要逐页面写死。

### 5.1 圆角

建议：

```text
button/input: 10–12px
small card:   14–16px
major card:   18–20px
hero panel:   20–24px
pill:         9999px
```

### 5.2 阴影

使用柔和、低对比阴影。

卡片默认：
- 非常轻微边框
- 柔和浅阴影

Hover：
- 轻微抬升
- shadow 轻微增强

不要出现厚重黑色阴影。

### 5.3 边框

减少“所有东西都靠灰色边框区分”。

优先：
- 留白
- 背景层级
- 柔和阴影
- 极淡 border

### 5.4 字体层级

统一：
- 页面主标题
- 页面说明
- Section 标题
- KPI 数值
- Card label
- 次级说明
- 辅助 metadata

数字 KPI 必须更有视觉权重。

---

## 6. App Shell 改造

### 6.1 左侧导航

保留现有布局和业务分组。

升级方向：
- Logo 区增加品牌感
- JL 图标更有辨识度
- “JL GROWTH”与中文产品名层级更清楚
- 可加入非常轻量的品牌短句，例如 `Growth Together`
- 当前导航使用更柔和、更完整的圆角高亮
- hover 有轻微背景变化
- icon 风格统一
- 大分组和子菜单保持清晰
- 不要让整个 sidebar 变成彩虹色

当前活动分组可以使用浅青绿背景 + 深青绿色文字。

### 6.2 Topbar

保持轻量：
- 搜索
- 账号
- breadcrumb

可增加：
- 更柔和边框
- 搜索框圆角
- icon 细节
- hover/focus 反馈

不要变成大型 header。

---

## 7. Page Header 改造

页面标题区应成为统一品牌表达区域。

建议结构：

```text
小分类 Label
页面标题
一句说明
可选的轻量背景图形 / 渐变 / illustration
```

例如数据统计：

```text
经营分析
数据统计
按业务领域和时间范围查看当前账号已记录的数据。
```

可以加入：
- 极淡背景渐变
- 山峰、成长、路径、叶片、阳光等抽象成长视觉
- 小型手绘感线条
- 不影响文字可读性

不是每页都必须放完整插画。复杂页面只需要轻量 header 氛围即可。

---

## 8. Tabs / Segmented Controls

现有：
- 页面一级 Tab
- 时间范围
- 数据维度
- 业务筛选

统一升级为现代 pill / segmented control。

要求：
- active 状态清楚
- active 可以白底 + shadow 或主色填充
- inactive 有轻量 hover
- 同一页面不同层级 Tab 视觉层级要区分
- 不要所有 Tab 都使用同样强度

---

## 9. KPI 卡片

这是本轮最重要的视觉升级组件之一。

结构建议：

```text
[小图标] 业务指标
大数值
轻量辅助信息
```

可使用：
- 柔和渐变
- 淡色装饰形状
- 小图标圆形底
- mini sparkline / 小趋势
- 极轻纹理

不同 KPI 可有不同色系：
- 开启对话：Mint / Teal
- 深入对话：Blue
- 分享故事：Coral
- 筛选：Yellow / Orange
- 会面：Purple

但：
- 数值仍保持深色高对比
- 卡片不能只靠颜色区分业务语义
- 颜色只增强视觉体验

---

## 10. 普通卡片 / Section Card

统一升级：
- 更柔和圆角
- 更舒展 padding
- section header 更明确
- card header 与内容区之间减少传统表格感
- divider 使用极淡线
- hover 只在可交互卡片上出现

---

## 11. 图表

图表视觉：
- 使用品牌色和辅助色
- 线条圆润
- area chart 可有淡渐变
- node / legend 更精致
- tooltip 使用统一浮层风格
- 坐标轴和 grid 减弱
- 数据本身优先，避免装饰压过信息

---

## 12. 空状态

全站重点升级。

不要只显示：

```text
暂无数据
```

建议结构：

```text
轻量插画 / icon
空状态标题
一句有行动感的解释
可选 CTA
```

例如：

```text
暂无趋势
先记录今天的工作量，数据会从第一步开始积累。
[去记录工作量]
```

视觉可以加入：
- 叶片
- 小山
- 成长路径
- 小型图表插画
- 太阳
- 星星

风格必须统一，不要每页完全不同。

---

## 13. 页面氛围差异

不同模块允许有轻微主题气质，但保持统一系统。

建议：

```text
首页              青绿 + 暖黄
今日工作          青绿 + 蓝
梦想与目标        紫 + 粉 + 青绿
日历              蓝 + 青绿
团队              青绿 + 蓝
学习中心          蓝 + 紫
复盘              紫 + 青绿
数据统计          青绿 + 蓝 + 多彩 KPI
财务              青绿 + 暖橙
收入模拟          蓝 + 紫
导入导出          蓝灰 + 青绿
设置              低彩度中性色 + 品牌绿
```

这里只是“氛围色”，不是每页重做一套设计系统。

---

## 14. 梦想 / 目标页面

梦想属于最适合“年轻化”的模块。

允许：
- 图片卡片
- 渐变蒙层
- 大圆角
- 标签
- 心愿/目标图形
- 更有情绪的空状态
- 图片 carousel 更有品牌感

目标卡片可以：
- 进度条
- 状态色
- 轻量图标
- 层级连接线

但不改变目标树/业务逻辑。

---

## 15. 团队页面

关系图允许更有活力：
- 节点保留成员自定义颜色
- 卡片圆角更柔和
- hover 更精致
- 连线降低视觉噪音
- 背景网格更淡
- detail dialog 与全局视觉保持一致

不要改变关系数据结构或节点交互逻辑。

---

## 16. 日历

日历需要现代化，但不能牺牲可读性。

建议：
- today 标记更柔和
- event 卡片更圆润
- 事件颜色更协调
- hover details 使用统一浮层
- toolbar 更轻
- month/week/day tab 与系统 segmented control 一致

不要改动：
- timezone
- drag/drop
- resize
- recurring scope
- contacts
- ICS 逻辑

---

## 17. 财务

财务应比其他页面稍克制。

可使用：
- 青绿表示正向
- 暖橙/珊瑚表示支出
- 蓝色用于预算/资金状态
- KPI 卡片有轻微色彩
- 图表更现代

避免：
- 红绿过饱和
- 股票交易软件风格
- 过多动效

---

## 18. 动效

允许轻量动效：
- hover
- button press
- card elevation
- segmented tab transition
- tooltip/popover
- disclosure 展开

建议 120–200ms。

禁止：
- 大面积 fade
- 页面切换动画
- loading 动画遮盖
- 弹跳
- 粒子
- 复杂背景动画

此前跨页面“闪动”问题已经多轮处理，本次不得引入新的页面切换动画或重新造成 layout shift。

---

## 19. 响应式

必须覆盖：
- 1440px
- 1280px
- 1024px
- ~390px mobile

重点：
- KPI 自动换行
- 卡片 spacing
- header decoration 在窄屏简化
- illustration 可隐藏或缩小
- sidebar/drawer 保持易用
- 不允许页面级横向溢出

## 24. 禁止事项

禁止：
- 改后端业务逻辑
- 改数据库
- 改 API 契约
- 改权限
- 改业务口径
- 大规模重排页面
- 修改核心工作流
- 为视觉重写 FullCalendar / React Flow
- 引入重型 UI 框架替换现有体系
- 每页各自硬编码一套视觉
- 使用高饱和彩虹色
- 过度 glassmorphism
- 页面切换动画
- 无意义动效
- 为美观牺牲信息密度
- 破坏 accessibility
- 破坏 mobile

## 26. 给 Codex 的直接指令

请对 JL团队生意成长管理系统做一轮前端视觉升级。

本轮目标不是重构产品，而是在保持现有功能、信息架构和主要布局基本不变的前提下，把当前偏传统企业后台的 UI 升级为年轻、活力、清爽、有成长感和品牌感的现代界面。

参考产品负责人提供的视觉稿，重点吸收：
- 青绿品牌主色
- 柔和彩色 KPI 卡片
- 更大的圆角
- 柔和阴影
- 更轻的页面背景
- 更现代的 segmented control
- 更有成长感的 Page Header
- 插画化 Empty State
- 少量蓝、紫、珊瑚、黄色辅助色
- 现代化图表
- 更友好、更年轻的导航与卡片

不要大改布局和业务交互。

先不要直接改代码。

第一步请：
1. 审计现有设计组件与 token；
2. 阅读本 Prompt；
3. 输出 `docs/ui-visual-upgrade-plan.md`；
4. 明确哪些修改属于全局组件，哪些属于页面特化；
5. 给出 UI-A / UI-B / UI-C / UI-D 四批实施顺序；
6. 停止，等待产品负责人确认。

不要部署生产，不创建 v1.0.0。
