## 2. 白屏问题：先复现，再修复

### 2.1 真实复现证据

在测试环境通过真实 Chromium 鼠标拖动周视图时间网格，先滚动到 `.fc-timegrid`，再从 09:00 拖动到 11:00，捕获到：

```text
[console:info] [calendar-select-diagnostic] {"view":"timeGridWeek","allDay":false,"start":"2026-09-15T09:00:00.000Z","end":"2026-09-15T11:00:00.000Z","startStr":"2026-09-15T09:00:00","endStr":"2026-09-15T11:00:00","timezone":"Asia/Shanghai"}
[pageerror] TypeError: Cannot read properties of undefined (reading 'title')
    at eventTooltip (.../src/features/calendar/calendar-page.tsx:109:11)
    at CalendarEventContent (.../src/features/calendar/calendar-page.tsx:118:19)
    at ...react-dom...
```

这是实际 pageerror/React 调用栈，不是推测。FullCalendar 的 `selectMirror` 临时事件没有业务 `extendedProps.event`，但 `CalendarEventContent` 无条件把它传入 `eventTooltip`，因此渲染阶段读取 `title` 直接崩溃并白屏。

同时确认拖动选择的 `Date` 对象在 `Asia/Shanghai` 下会发生墙钟时间转换；FullCalendar 的 `startStr/endStr` 才是当前日历视图的墙钟时间。修复后使用字符串优先，保留合法 fallback，并处理 `end` 缺失场景。

### 2.2 根因修复

- `selectMirror` 事件无业务对象时渲染安全的镜像内容，不调用业务 Tooltip；没有关闭 selectable、没有吞异常、没有刷新规避。
- 新建日程使用 `startStr/endStr`，对话框显示与拖动的本地墙钟时间一致；周视图、日视图均验证了起止时间和保存链路。
- 保留已有事件移动、缩放和重复事件处理。

## 3. Hover 层级根因修复

原问题是 Tooltip 位于 FullCalendar 局部 stacking context 内部的 `absolute` 节点，受到日期单元、today 标记、事件节点和容器裁切影响。

现在事件详情由 `createPortal(..., document.body)` 渲染为 `position: fixed`、`z-index: 100` 的浮层，脱离日历内部 stacking context；同时支持 hover/focus，按 viewport 右侧和底部边界翻转/夹紧，设置最大高度和滚动，监听 resize/scroll 重新计算。定位计算还会换算根节点缩放因子，覆盖 100% 与 125% 视觉缩放场景，不依赖 `opacity` 或 `setTimeout` 掩盖问题。

## 4. 复盘与路由切换闪动根因修复

- 复盘页面原先在查询 pending 时用整个 `LoadingState` 替换工作区，查询状态变化会卸载编辑器、侧栏和空状态结构，造成闪动/EmptyState 瞬时出现。
- 现在外层 `review-workspace`、主编辑区和历史侧栏始终保留；pending 使用等尺寸的局部 skeleton，错误也只在主编辑区内呈现。
- App Shell 的 Sidebar、Topbar、PageContainer 保持稳定。E2E 连续三轮遍历工作台、工作日志、日历、团队、财务、知识、复盘、分析、设置并返回首页，验证三者 DOM identity 不变，且没有 document-level overflow。
- 本轮未使用 React Profiler；上述 mount/unmount 结论来自真实路由和 tab 切换的 DOM identity 回归断言。
