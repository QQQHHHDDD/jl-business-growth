# 二、必须完成的 V1 发布阻塞项

## P0-01 首页核心聚合

补齐首页：

- 即将到来的日程；
- 团队摘要；
- 学习摘要；
- 财务摘要。

要求：

- 优先扩展聚合 Dashboard API，而不是前端并发十几个请求；
- 普通用户只能看到自己的数据；
- 响应式 UI 保持当前设计语言。

## P0-02 分析模块

补齐：

- 财务分析 API/UI；
- 团队分析 API/UI；
- 工作量、营业额、目标、财务、团队的数据可视化。

要求：

- 选择维护性好的图表方案；
- 不能只用静态演示数据；
- 时间范围/空状态/加载/错误状态正确；
- 不破坏现有 analytics API。

## P0-03 梦想图片关联

实现梦想与文件资产的真实关系。

要求：

- migration 只能新增，不修改已存在 migration；
- 支持上传图片、关联梦想、展示、替换/解除；
- 物理文件和 file_assets 权限正确；
- 删除梦想时明确处理关联关系；
- 删除账号时文件被清理；
- 管理员不得看到用户图片内容。

## P0-04 知识条目附件关联

后端已有能力的情况下补齐前端。

要求支持：

- 上传/选择文件；
- 保存 `file_ids`；
- 查看附件列表；
- 网页预览；
- 解除关联；
- 文件归属校验。

## P0-05 团队快照用户时区

修复 jobs：

- 每个用户按自己的 IANA timezone 判断应生成哪个业务月末快照；
- 默认 Asia/Shanghai；
- UTC 不得替代业务月；
- 延迟补跑生成时记录 `captured_late=true` 或现有等价字段；
- 幂等：同一用户同一业务月不得重复生成。

补 DST/跨月边界测试，即使主要用户在中国时区也要保证 IANA 语义正确。

## P0-06 统一账户删除

重构为一个可复用的账户删除服务，用户自删和管理员删除普通用户都调用同一核心流程。

至少完成：

- 阻断/防止删除过程中继续写业务数据；
- 失效所有会话；
- 收集用户物理文件；
- DB 事务删除；
- 删除物理文件；
- 失败文件进入可追踪日志/清理任务；
- 防止路径穿越；
- 管理员仍不能读取业务内容。

不要让管理员删除留下孤儿文件。

## P0-07 TEAM 导出与恢复

TEAM 独立导出必须输出稳定业务 code：

- `member_code`；
- `parent_member_code`。

不要再用“数据库 UUID + parent=NULL”的不可恢复格式。

增加自动测试：

```text
建立 3 层团队
→ 导出 TEAM
→ 导入到干净用户/测试数据集
→ 父子层级与关键字段一致
```

如果当前数据库没有稳定 member_code，请通过新 migration 增加，并设计已有成员的安全回填策略。

## P0-08 导入幂等

严格实现：

### WORKLOG
`(user_id, local_date)` upsert。

### TURNOVER
`(user_id, local_date)` upsert。

### TEAM
`(user_id, member_code)` upsert；第二阶段按 parent_member_code 恢复关系。

### FINANCE
不覆盖已有流水。构造稳定规范化重复指纹或等价可靠策略：

- 已存在完全相同流水 → 预览标记重复，默认跳过；
- 文件内部完全重复 → 同样标记；
- 不允许静默插入两份。

### IMPORT JOB
已 `COMMITTED` 的 job 再次 commit 返回明确冲突。

### FILE HASH
相同用户、相同 import type、相同 SHA-256 曾成功导入时显示“此前已导入过”的提醒；允许重新校验，但仍遵守业务幂等。

## P0-09 校验前置

把所有可确定问题移到 validation/preview：

- 财务 category 不存在；
- TEAM parent code 不存在；
- 重复 member_code；
- PV 与 net amount 不一致；
- 非法日期/金额/枚举；
- 重复财务流水；
- 将要 UPDATE 的工作量/营业额。

提交阶段仍要再次做数据库约束/并发安全校验，但正常用户不应第一次在 commit 时才知道模板基础错误。

## P0-10 金额精度

全面审计 money path：

- OpenAPI DTO；
- Go request/response；
- finance service；
- income simulation；
- import/export；
- analytics；
- frontend API/type/display。

人民币金额最终业务表示不得依赖 `float32/float64`。

选择以下之一并保持全项目一致：

- 推荐：`int64` 分；
- 或成熟 decimal 类型/十进制字符串契约。

PostgreSQL 保持 `numeric(14,2)` 或兼容的精确定点方案。

必须补 0.1、0.2、边界舍入、批量求和、导入导出 round-trip 测试。

不要修改《收入模拟器.xlsx》定义的业务公式，只改变数字表示和精度处理。
