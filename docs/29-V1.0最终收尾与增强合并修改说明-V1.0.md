## 1. 本轮已确认的业务定义

以下定义视为本轮正式产品规则，不再使用含糊名称。

### 1.1 收入模拟

- “个人使用 PV”指：**个人自己使用产生的 PV**。
- 不得把“个人使用 PV”命名为“个人圈 PV”。
- “Total Personal Circle PV / 个人圈总 PV”如界面需要展示，应明确表示为：
  - 个人使用 PV
  - + 顾客 PV
  - = 个人圈总 PV
- 收入模拟计算公式继续以当前已通过 Golden Test 的实现和项目收入模拟 Excel 为准。
- 本轮只修正命名、提示、展示和必要交互，不得擅自修改收入公式。

### 1.2 周期口径

- 本周：**周一至周日的自然周**。
- 本月：自然月。
- 自然年：1 月 1 日至 12 月 31 日。
- 财年：**9 月 1 日至次年 8 月 31 日**。
- 所有日期边界按照用户 IANA 时区解释。
- 页面日期范围采用用户可理解的闭区间展示，例如：
  - `2026-09-14 至 2026-09-20`
- 后端若使用半开区间实现查询，不得把技术区间直接展示给用户。

### 1.3 数据统计年度选择

原“本年”入口改为两个独立快速范围：

```text
本周 | 本月 | 自然年 | 财年 | 自定义
```

其中：

- 自然年：当前自然年；
- 财年：当前所在财年；
- 用户可自由切换；
- 不使用单独、含糊的“本年”。

# 3. A 类：V1.0.0 上线前必须修正

## A01 收入模拟：修正“个人圈 PV”概念

当前：

```text
个人圈 PV
顾客 PV
```

改为：

```text
个人使用 PV
顾客 PV
```

如需要展示汇总，可新增只读：

```text
个人圈总 PV
```

计算语义：

```text
个人圈总 PV = 个人使用 PV + 顾客 PV
```

禁止出现会让用户误解“个人圈 PV 已经包含顾客 PV、但又再次加顾客 PV”的表达。

### 验收

- 输入字段明确为“个人使用 PV”；
- 顾客 PV 独立；
- 现有计算结果不因纯命名修改发生变化；
- Golden Test 全部通过。

## A07 团队页与团队统计口径必须一致

当前人工截图出现：

- 团队页：成员 2、启用 2；
- 数据统计 → 团队：成员数 1、活跃成员 1、统计周期 1。

必须查明真实原因，不允许只改文字掩盖。

### 正式语义建议

数据统计 → 团队顶部 KPI：

- 当前成员数
- 当前启用成员
- 所选周期快照数

其中：

- 当前成员数、当前启用成员来自当前团队真实状态；
- 快照趋势来自团队历史快照；
- 所选周期没有快照时，明确显示“所选周期暂无团队快照”；
- 不得使用快照成员数冒充当前成员数。

### “统计周期”

若实际含义是快照数量，统一改为：

```text
快照数
```

### 验收

同一时刻：

```text
团队页当前成员数 == 团队统计“当前成员数”
团队页启用成员数 == 团队统计“当前启用成员”
```

当前类似：

> 永久删除当前账号的业务数据、上传文件和登录会话。此操作无法恢复。

改为更准确表达：

不得让用户误解：

> 点击删除后，所有历史备份中的数据也在同一瞬间物理消失。

不改变现有删除业务逻辑。

## B01 搜索结果支持记录级深链接

当前搜索结果只能进入对应模块，不能直接定位记录。

本轮批准实现记录级打开。

### 建议 URL 形式

不强制具体参数名，但应保持可复制、可刷新：

```text
/app/goals?goal=<id>
/app/calendar?event=<id>
/app/team?member=<id>
/app/knowledge?item=<id>
```

### 行为

搜索：

- 目标 → 打开该目标详情；
- 日历 → 定位并打开该事件；
- 团队 → 打开该成员详情；
- 学习 → 打开该学习项目详情。

刷新带深链接的 URL 后仍应恢复对应记录。

浏览器后退应返回搜索状态。

### API

如当前搜索 API 已返回稳定实体 ID，直接复用。

如未返回：

- 允许扩展 OpenAPI/Search DTO；
- 返回 `entity_type`、`entity_id` 和必要 display fields；
- 不扩大搜索权限；
- 不新增数据库表；
- 不改变搜索可见范围。

## B03 复盘“最近周期”改为真实保存记录

当前技术债务：

> 最近周期由前端猜测日期并调用单周期接口，不是真实历史列表。

本轮批准解决。

### 目标

“最近周期”只显示真正存在的已保存复盘。

### 建议 API

可新增只读列表 API，例如：

```text
GET /api/reviews?period_type=daily&limit=10
GET /api/reviews?period_type=weekly&limit=10
GET /api/reviews?period_type=monthly&limit=10
```

具体路径可按现有 OpenAPI 风格决定。

返回至少：

- review id
- period type
- period start
- updated_at

不需要新增数据库 migration，优先使用现有 reviews 表。

## B05 数据统计：图表达到基本分析价值

当前轻量 CSS 图形存在：

- 只有一根柱时仍占巨大画布；
- 无明显轴或比例；
- 0/1 个数据点时信息价值有限。

本轮批准优化。

### 至少要求

- 清晰的周期标签；
- 数值标签或 Tooltip；
- 合理的 Y 轴/比例语义；
- 多周期趋势可连续阅读；
- 0 数据不绘制假图；
- 仅 1 个数据点时，不展示“趋势”假象。

### 0 数据

显示紧凑空状态。

### 1 个数据点

显示：

> 当前只有 1 个统计周期，数据不足以形成趋势。

同时保留 KPI 和明细。

### 2+ 数据点

显示真实趋势。

### 图表依赖

可以：

- 继续增强现有轻量图；
- 或引入一个成熟、体积可接受的 React 图表库。

不得为了视觉效果改变数据统计口径。
